# Plan: Place catalog service skeleton (Spring + PostGIS + Flyway)

## Outcome

First **Java / Spring Boot 3** service on the signed house stack. Done when `services/catalog` boots on the existing root `compose.yml` network against **PostgreSQL 17 + PostGIS**, schema is **Flyway** (expand/contract only), and the first-commit seams from [`product/MVP.md`](../../product/MVP.md) §5 are in the database:

- **`category` and `facilities` are data**, not Java enums (table + FK / join; seeds match [[data/listing-types]]).
- **Ireland geography as data**, **32 counties including NI** (not ROI-only).
- **`Place.partner_id` nullable unused** — Chunk 1 seam, present, unused, no partner API.
- **Visit schema stub** with `visitType` (`VISITED` | `STAYED`) and `datePrecision` (`DAY` | `MONTH` | `YEAR` | `UNKNOWN`) from commit one. No Visit write API. No User/accounts API.
- **No booking columns on `Place`** (no availability, inventory, calendar, live rate, Stripe).

Actuator health + Micrometer `/actuator/prometheus` are scrapeable, logs are structured JSON, OpenTelemetry is hooked (OTLP no-op when unset), CI runs the module’s tests, and there is a minimal **Place** read API (or internal smoke) that proves the stack. **No booking. No consumer UI** — that is [[tickets/PRD-003]].

This planning PR contains **no application code**. The implementer lands the skeleton in a follow-up PR.

## Out of scope

- Vite + React PWA, pairing UI, check-off UX, My Places — [[tickets/PRD-003]]
- Curator seed, bulk import, coverage reporting — [[tickets/PRD-002]]
- Auth / OIDC / Spring Security beyond keeping health + prometheus reachable on the local compose network
- **User / accounts / identity API** — deferred. No `User` table required this ticket. `visit.user_id` is an unenforced UUID column (no FK to a users table).
- **Visit write endpoints, check-off API, Visit read API** — deferred to the product tickets that need them. **Visit Flyway table is in scope** (schema stub only).
- Images / object storage, MinIO, Mailpit, Tempo
- Booking, Stripe, inventory, calendars, partner portal — [[tickets/PRD-004]]. Do not add those columns on `Place`.
- Playwright (that is [[tickets/WF-011]] once a UI exists)
- FastAPI, TypeScript API, Next.js, Neon, restoring `legacy-platform`

## Module layout

Investigate-first: there is **no** `src/`, `services/`, or Maven/Gradle tree today. Canonical runtime is **one** root [`compose.yml`](../../compose.yml) (`ops/compose.yml` is an include wrapper). Postgres is `postgres:17-alpine`, db `ops`, **no PostGIS**, no app service. Workspace image already has **Java 21**. CI is [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) (pytest + compose stack). Categories in the vault: [[data/listing-types]]. Geography: [[data/regions]] (Ireland / 32 counties).

**Do not invent a second house.** Add one module to this repo and this compose file:

```
services/catalog/          Spring Boot 3 + Java 21, Maven wrapper (`mvnw`)
  src/main/java/island/catalog/
  src/main/resources/db/migration/    Flyway
compose.yml                add service `catalog`; switch postgres image to PostGIS
ops/observability/prometheus.yml     scrape catalog:8080 `/actuator/prometheus`
.github/workflows/ci.yml  add a `catalog` job (setup-java 21 + `./mvnw test`)
```

- **One Postgres container**, not a second database engine. Change the existing `postgres` image to `postgis/postgis:17-3.5` (or `…-alpine`). Keep db `ops` for MCP. Create db `catalog` in init; Flyway owns that schema only.
- Runtime image: small `services/catalog` Dockerfile (Temurin 21 JRE). Do not reuse the `workspace` toolchain image as the API.
- Package `island.catalog` (public brand unset — do not print “my-island” on a customer surface).
- Prefer **Spring Data JDBC** (or JPA without `@Enumerated` category/facilities). Category and facilities are rows.

Local volume `ops_pg` will not magically grow PostGIS — implementer must note `down -v` for existing laptops. CI volumes are ephemeral.

## Steps

1. **Spring Boot 3 skeleton** — Java **21** (already in `.devcontainer/Dockerfile`; do not chase Java 25). Spring Boot 3.x current stable. Maven wrapper committed so CI does not need Maven baked into the workspace image. Starters: web, actuator, jdbc, flyway, micrometer-registry-prometheus. No Stripe starters.
2. **Place + category + facilities as data** — Flyway tables: `category` (seed `poi`, `experience`, `campsite`, `bnb` matching [[data/listing-types]]), `facility` + `place_facility` join (small fixed MVP set as **rows**, not a Java enum), `county` (**32 Irish counties including NI**, country `IE`, as data — not hardcoded in Java), `place` (`category_id` FK, slug, name, description, town, `published`, **nullable unused `partner_id`**). `Place.location` is PostGIS `geography(Point,4326)` (store lon/lat as well if it keeps JDBC simple). **Forbidden:** `enum Category { CAMPSITE }`, a facilities enum, or any campsite-only closed type. Java types are entities/records with slug/id. **No booking columns on `Place`** (no availability, inventory, calendar, live rate, Stripe ids). Indicative `price_band` (null | FREE | 1..3) is directory metadata, not a bookable rate — include it only as that; never a live price.
3. **Visit schema stub (this ticket, not deferred)** — Flyway `visit` table from commit one per MVP §5: `id`, `user_id` (UUID, **no FK** — User table deferred), `place_id` FK, `visit_type` (`VISITED` | `STAYED`, check constraint or lookup — **not a boolean**), `occurred_on` nullable, `date_precision` (`DAY` | `MONTH` | `YEAR` | `UNKNOWN`), optional private `note`, `created_at`, `synced_at`. `visitType` exists for every visit even though only campsite/B&B surface STAYED later. No Visit/check-off HTTP API this ticket. A migration test that inserts a row is enough.
4. **PostGIS + Flyway** — `CREATE EXTENSION IF NOT EXISTS postgis` in V1. Expand/contract only: never drop+rename in one version. No ad-hoc DDL against shared envs.
5. **Actuator** — `health` (liveness/readiness including datasource; assert PostGIS in a test), `prometheus`. Leave these reachable on the compose network without login for local scrape. Scrape auth is a pre-prod STACK gap, not this ticket.
6. **JSON logs + OTel hooks** — structured JSON on stdout (`service`, `env`, `version`, `traceId`). Micrometer Tracing + OpenTelemetry SDK autoconfigure; OTLP exporter **no-op** when `OTEL_EXPORTER_OTLP_ENDPOINT` is unset. Do not add Tempo this ticket.
7. **Minimal Place read API / smoke** — enough to prove the stack, not DIR-*. Suggested: `GET /api/v1/categories`, `GET /api/v1/counties`, `GET /api/v1/places` (empty list or one test fixture). No write/curator API (PRD-002). No `/visits` routes. Document the Place JSON shape in the implement PR so [[tickets/PRD-003]] can stub.
8. **Compose wiring** — `catalog` service on the **same** compose file/network, `depends_on: postgres` healthy, JDBC to `postgres:5432/catalog`. Host port offset if needed (stack already uses 5433/3030/…). Add Prometheus scrape job `catalog`. JSON logs to stdout (docker logs / Loki later). Do not add a second Grafana stack.
9. **CI module tests** — new job in the **existing** workflow (not a second CI house): `actions/setup-java` Temurin 21 + `services/catalog/mvnw test`. Prefer Testcontainers `postgis/postgis:17-3.5` so the python `unit` job stays compose-free. Assert Flyway applies `visit` + 32 counties including NI. Do not add Playwright. Do not keep a red job “for later”.
