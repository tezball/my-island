# Plan: Place catalog service skeleton (Spring + PostGIS + Flyway)

## Outcome

First **Java / Spring Boot 3** service on the signed house stack. Done when `services/catalog` boots on the existing root `compose.yml` network against **PostgreSQL 17 + PostGIS**, schema is **Flyway** (expand/contract only), `Place.category` is a **table/FK** (not a closed Java enum), Actuator health + Micrometer `/actuator/prometheus` are scrapeable, logs are structured JSON, OpenTelemetry is hooked (OTLP no-op when unset), CI runs the module’s tests, and there is a minimal read API (or internal smoke) that proves the stack. **No booking. No consumer UI** — that is [[tickets/PRD-003]].

This planning PR contains **no application code**. The implementer lands the skeleton in a follow-up PR.

## Out of scope

- Vite + React PWA, pairing UI, check-off, My Places — [[tickets/PRD-003]]
- Curator seed, bulk import, coverage reporting — [[tickets/PRD-002]]
- Auth / OIDC / Spring Security beyond keeping health + prometheus reachable on the local compose network
- Visit / User / accounts, images/object storage, MinIO, Mailpit, Tempo
- Booking, Stripe, inventory, calendars, partner portal — [[tickets/PRD-004]]
- Playwright (that is [[tickets/WF-011]] once a UI exists)
- FastAPI, TypeScript API, Next.js, Neon, restoring `legacy-platform`

## Module layout

Investigate-first: there is **no** `src/`, `services/`, or Maven/Gradle tree today. Canonical runtime is **one** root [`compose.yml`](../../compose.yml) (`ops/compose.yml` is an include wrapper). Postgres is `postgres:17-alpine`, db `ops`, **no PostGIS**, no app service. Workspace image already has **Java 21**. CI is [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) (pytest + compose stack). Categories in the vault: [[data/listing-types]]. Geography: [[data/regions]] (Ireland / 32 counties).

**Do not invent a second house.** Add one module to this repo and this compose file:

```
services/catalog/          Spring Boot 3 + Java 21, Maven wrapper (`mvnw`)
  src/main/java/island/catalog/
  src/main/resources/db/migration/    Flyway
compose.yml                add service `catalog`; switch postgres image to PostGIS
ops/observability/prometheus.yml     scrape catalog:8080 `/actuator/prometheus`
.github/workflows/ci.yml  add a `catalog` job (setup-java 21 + `./mvnw test`)
```

- **One Postgres container**, not a second database engine. Change the existing `postgres` image to `postgis/postgis:17-3.5` (or `…-alpine`). Keep db `ops` for MCP. Create db `catalog` in init; Flyway owns that schema only.
- Runtime image: small `services/catalog` Dockerfile (Temurin 21 JRE). Do not reuse the `workspace` toolchain image as the API.
- Package `island.catalog` (public brand unset — do not print “my-island” on a customer surface).
- Prefer **Spring Data JDBC** (or JPA without `@Enumerated` category). Category is a row.

Local volume `ops_pg` will not magically grow PostGIS — implementer must note `down -v` for existing laptops. CI volumes are ephemeral.

## Steps

1. **Spring Boot 3 skeleton** — Java **21** (already in `.devcontainer/Dockerfile`; do not chase Java 25). Spring Boot 3.x current stable. Maven wrapper committed so CI does not need Maven baked into the workspace image. Starters: web, actuator, jdbc, flyway, micrometer-registry-prometheus. No Stripe starters.
2. **Place + category as data** — Flyway tables: `category` (seed `poi`, `experience`, `campsite`, `bnb` matching [[data/listing-types]]), `county` (32 Irish counties as rows, country `IE`), `place` (`category_id` FK, slug, name, description, town, `published`, nullable `partner_id`), `facility` + join table (data, not a Java enum). `Place.location` is PostGIS `geography(Point,4326)` (store lon/lat as well if it keeps JDBC simple). **Forbidden:** `enum Category { CAMPSITE }` or any campsite-only closed enum. Java types are entities/records with slug/id.
3. **PostGIS + Flyway** — `CREATE EXTENSION IF NOT EXISTS postgis` in V1. Expand/contract only: never drop+rename in one version. No ad-hoc DDL against shared envs.
4. **Actuator** — `health` (liveness/readiness including datasource; assert PostGIS in a test), `prometheus`. Leave these reachable on the compose network without login for local scrape. Scrape auth is a pre-prod STACK gap, not this ticket.
5. **JSON logs + OTel hooks** — structured JSON on stdout (`service`, `env`, `version`, `traceId`). Micrometer Tracing + OpenTelemetry SDK autoconfigure; OTLP exporter **no-op** when `OTEL_EXPORTER_OTLP_ENDPOINT` is unset. Do not add Tempo this ticket.
6. **Minimal read API / smoke** — enough to prove the stack, not DIR-*. Suggested: `GET /api/v1/categories`, `GET /api/v1/counties`, `GET /api/v1/places` (empty list or one test fixture). No write/curator API (PRD-002). Document the JSON shape in the implement PR so [[tickets/PRD-003]] can stub.
7. **Compose wiring** — `catalog` service on the **same** compose file/network, `depends_on: postgres` healthy, JDBC to `postgres:5432/catalog`. Host port offset if needed (stack already uses 5433/3030/…). Add Prometheus scrape job `catalog`. JSON logs to stdout (docker logs / Loki later). Do not add a second Grafana stack.
8. **CI module tests** — new job in the **existing** workflow (not a second CI house): `actions/setup-java` Temurin 21 + `services/catalog/mvnw test`. Prefer Testcontainers `postgis/postgis:17-3.5` so the python `unit` job stays compose-free. Do not add Playwright. Do not keep a red job “for later”.
