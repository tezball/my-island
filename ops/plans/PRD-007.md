# Plan: Research→leads pipeline acceptance (Wave 1)

## Outcome

Product acceptance for **Research Wave 1**: deposits and updates in [`data/leads/places.jsonl`](../../data/leads/places.jsonl) match the **landed** [`data/leads/schema.json`](../../data/leads/schema.json) (PR #14 / [[tickets/PRD-006]]). Done when the Wave 1 bar in [`product/WAVE-1.md`](../../product/WAVE-1.md) is checkable from this plan + [[tickets/PRD-007]] verify — **no application code**. Leads are not published places.

## Out of scope

- A second lead schema, DTO, or field list
- Scraper code
- Spring / Flyway import implementation (ACs live on [[tickets/PRD-008]])
- Auto-publish or waiving counsel ([[tickets/PRD-009]] stays the gate)
- Consumer PWA, booking, brand lock
- Broader CUR-* bulk-import / coverage ([[tickets/PRD-002]])

## Wave 1 bar

1. **Schema-only.** Every JSONL line is one object with all `schema.json` `required` keys: `id`, `name`, `place_type`, `country`, `source_url`, `source_name`, `fetched_at`, `licence`, `status`, `dedupe_key`. `additionalProperties: false` — extra keys fail CI.
2. **Pytest is the contract.** `python3 -m pytest ops/tests/test_leads.py -q` stays green on every Wave 1 deposit PR.
3. **Idempotency.** Same `dedupe_key` (`place_type:county-slug:name-slug`) or same website host + similar name → **update the existing line**. No duplicate `id`. Research `status` on deposit is `lead` (never `promoted`).
4. **Provenance.** `source_url`, `source_name`, `fetched_at`, `licence` on every row. `email_public` is public business mail only (no Gmail/Yahoo / named personal inboxes). Omit unknown optionals; never `"-"`.
5. **Not the catalog.** Research does not write Spring/Postgres and does not publish. Promote/create **draft** Places is [[tickets/PRD-008]]. Publish still needs [[tickets/PRD-009]].

## Steps
