# Plan: Dev Container, compose, and CI

## Outcome

Laptop, Dev Container, Cloud Agent, and CI all start the same Compose stack and run the same tests. Done when `./scripts/dev up` and `./scripts/dev test` are documented, wired, and green in Actions.

## Out of scope

Consumer API, Playwright browsers, Jenkins, prod compose, merging PRs.

## Steps

1. Canonical `compose.yml` at repo root (ops stack + `workspace` image). Keep `ops/compose.yml` as a thin include so existing commands still work.
2. `.devcontainer/` uses that compose file (`service: workspace`).
3. `.cursor/environment.json` + Docker-in-Docker image: `start` brings the daemon up, then `docker compose up`.
4. `./scripts/dev` for `up` / `down` / `test`. Pytest for ops scripts + stack health.
5. GitHub Actions runs the same compose + pytest path.

## Verify

- [ ] `docker compose config` succeeds
- [ ] `./scripts/dev test` unit tests pass without the stack
- [ ] `./scripts/dev up` then `REQUIRE_STACK=1 ./scripts/dev test` — Grafana health + Postgres
- [ ] `.github/workflows/ci.yml` uses `compose.yml`, not a second stack
- [ ] `.devcontainer/devcontainer.json` `dockerComposeFile` is `../compose.yml`

## MCP / env

Local compose required for stack tests. No prod Grafana.
