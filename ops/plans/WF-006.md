# Plan: Company OS vault, agent org, and runbooks

## Outcome

The repo is the source of truth for a fully automated AI company. Agents can open `ops/` in Obsidian, pick one ticket, follow a runbook, and know which role they are. Done when the vault taxonomy, charter, roster, runbooks, templates, and starter product tickets exist — without rebuilding the consumer app.

## Out of scope

- Java/Spring marketplace or directory application code
- Moving or deleting `docs/` (legacy booking platform)
- Rewriting `product/` canon (directory-first MVP stands)
- Enabling Cursor Automations (that is [[tickets/WF-003]])
- Merging this PR

## Migration choices

1. **Vault path stays `ops/`.** `docs/` already has an old Obsidian config and describes the deleted booking platform. `product/` is living canon. Collapsing those into `docs/` would mix history, spec, and tickets. Agents already start at `ops/HOME.md`.
2. **Do not relocate `docs/` or `product/`.** Point at them from the vault. Call them history vs canon in README.
3. **Long-term company = Ireland stays marketplace.** Current MVP = checkable directory (`product/MVP.md`). Starter `PRD-*` tickets are the directory; a gated marketplace epic sits in inbox.
4. **Grok Bot writes notes and tickets. Cursor agents change this repo.** Documented in [[agents/GROK_VS_CURSOR]].

## Steps

1. Charter, naming, plugin recommendations, company notes.
2. Agent roster (one short note per role) + Grok vs Cursor map.
3. Runbooks: ticket loop, guest support, listing/region rollout, weekly digest.
4. Templates: epic, story, bug, incident, daily. `new_ticket.py` to allocate ids.
5. Starter tickets: PRD-000 (directory epic), PRD-001–003 (first stories), PRD-004 (marketplace epic, gated).
6. `next_ticket.py` skips `type: epic` so agents work children, not the parent.
7. README + AGENTS.md + cursor rule: this repo is the company OS.
8. Pytest for vault layout and ticket frontmatter.
