# Plan: Cloud Agent mcp-grafana and Postgres-RO against local compose

## Outcome

A Cloud Agent on this repo can **read** local compose Grafana + Postgres the same way laptop Cursor does: PromQL/LogQL via `mcp-grafana --disable-write` (or documented HTTP equivalents) and `ops_reader` `SELECT` on catalog `place`. Done when grants land, MCP attach (or honest HTTP fallback) is documented, vault tests are green, and a PR links this ticket. Human merges.

## Out of scope

- Staging/prod remote Grafana MCP ([[tickets/WF-004]])
- Always-on EU staging ([[tickets/WF-010]])
- Expanding [[tickets/WF-004]] / [[tickets/WF-010]] or marking them done
- Product UI, booking, or expanding [[tickets/PRD-001]]
- Enabling chaos on default compose or required CI
- Merge, prod writes, secrets in notes
- Flyway `V6` in the catalog module (Testcontainers has no `ops_reader`; grants stay in compose SQL + `./scripts/dev up`)

## Steps

1. Grant `ops_reader` `CONNECT` / `USAGE` / `SELECT` on db `catalog` (schema `public`, including `place`). Re-apply on every `./scripts/dev up` so existing volumes get it. `REVOKE` writes. No write role.
2. Postgres cannot `SELECT` across databases from one DSN. Keep `postgres` MCP on db `ops` (`mcp_ping`). Add `postgres-catalog` MCP → `postgresql://ops_reader@127.0.0.1:5433/catalog` (SELECT only).
3. Document Cloud Agent attach in [[workflow/MCP]], [[workflow/LOCAL]], [[workflow/STACK-E2E-place-stub]], `AGENTS.md`, and the STACK-E2E runbook: laptop `.cursor/mcp.json` does **not** follow Cloud Agents; `.cursor/environment.json` has no MCP attach field. Human adds matching **stdio** servers on cursor.com (MCP dropdown / team Integrations) so they run **in the VM** against `127.0.0.1:3030` / `5433`. HTTP MCP is proxied off-VM — do not point it at loopback. Until that dashboard attach exists, HTTP PromQL (runbook) is the equivalent.
4. Vault tests for grants SQL, second DSN, docs, ticket/plan/board. Chaos stays out of CI yaml.

## Verify

- [ ] `ops_reader` can `SELECT` `place` on db `catalog`; `INSERT`/`UPDATE`/`DELETE` denied
- [ ] `.cursor/mcp.json` has `grafana --disable-write`, `postgres` → db `ops`, `postgres-catalog` → db `catalog`
- [ ] MCP.md / LOCAL / STACK-E2E / AGENTS.md document Cloud Agent stdio-on-dashboard vs HTTP fallback
- [ ] PromQL HTTP `up{job="catalog"}` = 1 with compose up
- [ ] `python3 -m pytest ops/tests -q -m "not stack"` green
- [ ] No secrets; no merge; CI yaml has no chaos profile

## MCP / env

Local compose required to prove grants + HTTP PromQL. This Cloud Agent toolbox has no `grafana` / `postgres` MCP until a human adds dashboard stdio — HTTP is the documented equivalent. Prod Grafana is not required.
