# Plan: Simple local CLI for start/stop/test

## Outcome

One entrypoint Terry can remember (`./scripts/app`) starts, stops, and tests the local Halfdoor stack. Done when start/stop/test/help work, LOCAL.md has the one-liner, and `test` prints a clear PASS/FAIL report.

## Out of scope

- Consumer PWA / Next.js ([[tickets/PRD-003]])
- Enabling chaos by default
- Rewriting `compose.yml`
- Merging the PR
- Secrets in notes

## Steps

1. File [[tickets/WF-021]] (next free after WF-020; skip 019 claimed by PR #31). Owner: automation-expert.
2. Add `start` / `stop` on `./scripts/dev` (start = `up` + optional browser tabs + ready summary; stop = `down` + clear message). Keep `up` / `down` / `test` for CI and Cloud Agent `start.sh`.
3. Add `./scripts/app` as the human wrapper: `start` / `stop` / `test` / `help`.
4. `test` ensures the stack is up, runs `./scripts/dev test` (pytest, `REQUIRE_STACK=1`), `services/catalog/mvnw -B test`, and catalog health + create/list/get smoke (`categoryId`/`countyId`/`latitude`/`longitude`). One-screen PASS/FAIL; exit 0 iff all green.
5. Open browser tabs only when a GUI exists (`open` / `xdg-open`); skip on Cloud Agent / CI.
6. Document the one-liner in [[workflow/LOCAL]].

## Verify

- [ ] `./scripts/app help`
- [ ] start / stop / test as on the ticket
- [ ] chaos not on default start
- [ ] `python3 -m pytest ops/tests -q -m "not stack"`

## MCP / env

Local compose required to prove start/test. No prod Grafana. Postgres MCP stays read-only.
