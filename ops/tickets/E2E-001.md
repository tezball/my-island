# E2E-001 — Place listing stub API (create/list/get) — e2e workshop

## Outcome

Thin HTTP stub on the Spring catalog so agents can demo **create → list → get** with automated tests. Success is **plumbing + demo-able tests**, not polish. Extends [[tickets/PRD-001]] (Engineering may sequence this with or right after the skeleton).

## Notes

Align with PRD-001 Place shape ([`product/MVP.md`](../../product/MVP.md) §5, [`product/STACK.md`](../../product/STACK.md)). Categories are data: seed slugs `poi` | `experience` | `campsite` | `bnb` ([[data/listing-types]]). Counties are data: **32 including NI**.

**Public brand naming is OPEN.** Do not put Halfdoor, Inis, or Ireland Stays in user-facing strings as the product name. Repo stays `tezball/my-island`.

**Workshop exception:** no auth on this stub. Call that out in the implement PR so it is not copied into later product APIs.

This ticket is product ACs + workflow only until status is `implement`. Do not land application code on this intake PR.

Workshop: [[workshops/e2e-place-stub]]. Canvas: [[workflow/e2e-place-stub]].

## Verify

- [ ] `POST /api/v1/places` creates a place: `name` required, `categorySlug` required (`poi` | `experience` | `campsite` | `bnb` seed), optional `town`, optional `countySlug` (32 counties incl NI), optional `lon` + `lat` → PostGIS when **both** present (one without the other → 400)
- [ ] Response returns `id` (UUID) + the resource shape
- [ ] `GET /api/v1/places` lists places (includes the created one)
- [ ] `GET /api/v1/places/{id}` returns one or 404
- [ ] Missing `name` / unknown `categorySlug` → **400** not 500
- [ ] No auth for workshop stub (document as workshop exception)
- [ ] No booking / Stripe / inventory columns
- [ ] Automated tests: create → list contains `id` → get by id; CI green
- [ ] Out: UI, images, visits API, partner portal, search polish, pagination polish, bulk import
