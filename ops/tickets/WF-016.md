# WF-016 — Align E2E-001 place JSON fields with catalog stub

## Outcome

Workshop ACs, canvas, LOCAL curl, and the running Spring stub use the **same** JSON field names for create/list/get. Agents following [[tickets/E2E-001]] can POST a minimal place without guessing.

## Notes

Found on happy-path MCP review [[runs/e2e-place-stub-mcp-2026-09-06]] (HTTP against `http://127.0.0.1:8081`, chaos off).

| Surface | Create fields |
|---|---|
| [[tickets/E2E-001]] + canvas | `name`, `categorySlug` required; optional `town`, `countySlug`, `lon`+`lat` |
| Running stub (PR #21) | `name`, `categoryId`, `countyId` required (`@NotBlank`); `latitude`/`longitude` |
| This review POST with E2E-001 names | **400** `countyId must not be blank` |

Happy-path create **does** work with the stub contract (`categoryId`/`countyId`). Do not silently rewrite E2E-001 ACs here. Workshop Lead picks: update ACs+canvas+LOCAL to match the stub, or change the stub to match ACs. Implementation of a stub change is eng-backend on a later `implement` session — not this review PR.
