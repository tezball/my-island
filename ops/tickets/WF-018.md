# WF-018 — Align E2E-001 place JSON fields with catalog stub

## Outcome

Workshop ACs, canvas, LOCAL curl, and the running Spring stub use the **same** JSON field names for create/list/get. Agents following [[tickets/E2E-001]] can POST a minimal place without guessing.

## Notes

Found on the E2E workshop 2026-09-06 happy path ([[runs/e2e-place-stub-mcp-chaos-2026-09-06]]; also the happy-path-only pass on superseded PR #28). Chaos was not required to see this.

| Surface | Create fields |
|---|---|
| [[tickets/E2E-001]] + canvas | `name`, `categorySlug` required; optional `town`, `countySlug`, `lon`+`lat` |
| Running stub (PR #21) | `name`, `categoryId`, `countyId` required (`@NotBlank`); `latitude`/`longitude` |
| POST with E2E-001 names | **400** (`countyId must not be blank`) |

Happy-path create **does** work with the stub contract (`categoryId`/`countyId`). **Workshop Lead:** stub wins. Docs only (no Java): E2E-001 ACs + canvas use `categoryId` / `countyId` / `latitude` / `longitude`. [[workflow/LOCAL]] curl already matches.
