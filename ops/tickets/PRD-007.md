# PRD-007 — Research→leads pipeline acceptance

## Outcome

Acceptance criteria for **Research depositing leads** into [`data/leads/`](../../data/leads/README.md). Leads are **not** published places. Every deposit is JSONL + provenance. Research may not skip to publish.

## Notes

CEO seed path (Orchestrator, 2026-09-05): Research collects aggressive multi-source **leads** into `data/leads/`. The store and JSON Schema are [[tickets/PRD-006]] (merged). This ticket is the **pipeline bar**, not a second schema. Do not invent fields — follow schema as defined under [`data/leads/`](../../data/leads/README.md).

Owner: **product** (acceptance). Research executes as **content-seo**. Relates to [[tickets/PRD-002]] (curator seed). Promote-from-lead is [[tickets/PRD-008]]. Counsel before publish is [[tickets/PRD-009]].

Required provenance (schema): `id`, `name`, `place_type`, `country`, `source_url`, `source_name`, `fetched_at`, `licence`, `status`, `dedupe_key`. County and category (`place_type`) are hints — omit county when unknown; do not invent. Idempotency: same `dedupe_key` or same website host + similar name → update the line, do not duplicate. No personal-mailbox scrape into git. `status` starts as `lead`. Depositing a lead is **not** publish.

## Verify

- [ ] Plan (or this ticket) cites [`data/leads/schema.json`](../../data/leads/schema.json) required fields; no competing schema
- [ ] JSONL + provenance required on every Research deposit (`source_url`, `source_name`, `fetched_at`, `licence`)
- [ ] Idempotency: `dedupe_key` / website+name update-in-place, no duplicate ids
- [ ] No PII scrape into git (no personal Gmail/Yahoo or named inboxes in `email_public`)
- [ ] Source + licence recorded; county/category hints only (omit rather than invent)
- [ ] Research **cannot** mark a lead `promoted` or write the live catalog from this pipeline
- [ ] No scraper, Spring import, or consumer app code in the implementing PR
- [ ] `python3 ops/scripts/board_sync.py` if ticket status changes
