# Recommended Obsidian plugins

The vault is **`docs/`** only. Dataview `FROM "ops/tickets"`. Start at [`HOME.md`](../HOME.md) (dashboard) then [[ops/HOME]] or a [[ops/dashboards/_index|role dashboard]].

Core settings in `docs/.obsidian/` are committed. **Do not commit plugin binaries** (`main.js`). Install community plugins on your machine.

## Core (enabled in `.obsidian/core-plugins.json`)

| Plugin | Why |
|---|---|
| **Bases** | Interactive tables on [[ops/dashboards/_index]] (`.base` files). Not ticket SoT. |
| Templates | New notes from `ops/templates/` |
| Daily notes | `ops/daily/YYYY-MM-DD.md` from `ops/templates/daily` |
| Properties | Ticket frontmatter (`status`, `priority`, `owner`) |
| Backlinks / outgoing links | Follow `[[wikilinks]]` |
| Graph | See ticket ↔ plan ↔ run |
| Canvas | Workshop canvases under `ops/workflow/` |

Daily notes: folder `ops/daily`, format `YYYY-MM-DD`, template `ops/templates/daily`.

Kanban uses a community plugin; `ops/BOARD.md` is still generated by script.

## CSS snippet

`company-os` in `.obsidian/snippets/company-os.css` — enabled via `appearance.json`. Tokens and `cssclasses`: [[ops/company/VAULT_DESIGN]].

## Community (listed in `.obsidian/community-plugins.json`)

Install via Settings → Community plugins → Browse. Restricted mode off.

| Plugin id | Name | Use |
|---|---|---|
| `obsidian-kanban` | Kanban | Optional view of [[ops/BOARD]] and [[ops/MILESTONES]]. **Ticket SoT = frontmatter + `board_sync.py`.** |
| `dataview` | Dataview | Markdown fallback queries (examples in [[ops/data/_index]] and role dashboards). |
| `templater-obsidian` | Templater | Optional; core Templates is enough for agents |
| `obsidian-tasks-plugin` | Tasks | Checklists in runbooks and dailies |
| `calendar` | Calendar | Jump to daily notes |
| `advanced-canvas` | Advanced Canvas | Workshop canvases |
| `omnisearch` | Omnisearch | Fast search |
| `smart-connections` | Smart Connections | Related notes |

**Homepage** (`homepage`) is optional. Install it and set the homepage note to `HOME.md`.

Do not copy historical plugin folders from `leads/` or `automation/`.

## Bases vs Dataview

| | Bases | Dataview |
|---|---|---|
| Where | `ops/dashboards/*.base` | fenced `dataview` in markdown |
| Best for | Humans in Obsidian (sortable views) | GitHub + readers without Bases UI |
| SoT? | No — filters ticket frontmatter only | No |

## Dataview snippets

`FROM` is vault-relative. Vault root is `docs/`, so tickets are `"ops/tickets"`.

Tickets in flight:

````markdown
```dataview
TABLE status, priority, owner
FROM "ops/tickets"
WHERE id AND status != "done" AND type != "epic"
SORT priority ASC, id ASC
```
````

Incidents:

````markdown
```dataview
TABLE status, owner, blocked_reason
FROM "ops/tickets"
WHERE type = "incident"
SORT file.name DESC
```
````

## Agents and Obsidian

Agents edit markdown in git. They do not click the Obsidian UI. Humans use Obsidian to read the vault. After pulling, if Kanban looks stale, run `python3 ops/scripts/board_sync.py`.
