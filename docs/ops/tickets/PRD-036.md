# PRD-036 — Host and Stay thin slice

## Outcome

Same as [`product/HOST-STAY.md`](../../product/HOST-STAY.md). A **Host** is a role on the signed-in account. A host adds one or more **Stays**. A Stay is a new place, not a claim on the 101 POIs.

Kinds, stored and shown with these words: campsite, bed and breakfast, apartment, glamping, lodge. No hotels. One page per Stay, not a page per pitch or room.

The wizard asks for kind, title, description (required), images (1 to 8; cover cropped to 1600×900, others to 1200×800), cost optional EUR, phone optional, email optional, website optional, and location required (drop a pin or enter latitude and longitude; county comes from the pin and is one of the 32 Irish counties).

A Stay stays hidden from the public until automatic review finishes clean. Any edit hides it again until review passes. Review error or timeout keeps it hidden. Review order is tech, then fit, then conduct. Fit failures are feedback. A ban hides every Stay of that host and blocks new submissions. They can still sign in and read the reason. Phone and email show on the public page when present.

Admin is the Google account `tezball86@gmail.com`, checked on the server. The console shows all Stays, Stays stuck in review, and banned accounts. Actions are run review again and unban. Unban does not publish. There is no hand-publish.

A website, if present, must load. Review does not follow redirects. A 3xx is “did not load”, the same as a down site.

Dates, payment, messages, and hotels are out. Do not promote [[ops/tickets/PRD-016]]–[[ops/tickets/PRD-029]]. Public Place POST stays closed. Host writes go through the authenticated host API.

Demo password accounts use the existing seed Guest password (`CATALOG_SEED_GUEST_PASSWORD`, `guest` in local compose): `host-campsite`, `host-submitted`, `host-rejected`, `host-banned`. `tezball86@gmail.com` is not pre-filled with a Stay.
