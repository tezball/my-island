# PRD-030 — Guest been and want lists on map

## Outcome

A **signed-in Guest** can review **been** and **want** (plan-to-go) VisitIntents on a **map or a list**. Same Spring catalog + Vite PWA. Reuse the existing VisitIntent API and Explore Leaflet map. `/lists` today is **list-only** — this ticket adds the missing map (and a list/map toggle) so a profile-style review works. **Do not** implement [[ops/tickets/PRD-013]] as written (My Places counts, 32-county progress, CSV export).

## Notes

**2026-09-20 gap.** [[ops/tickets/PRD-015]] (#97) is on `main`: `VisitTicks` on Explore/detail, private `/lists` for been / want / never. Terry cannot see been/want on a **map**. That is this ticket, not a reopen of PRD-013.

**Reuse:** `GET`/`PUT`/`DELETE` VisitIntent under `/api/v1/me/…`, published Place coords, `MapView` (Leaflet + OSM). One VisitIntent per Guest + Place. Lists stay **private**. Public Place JSON stays **anonymous been count** only.

**UI:** signed-in profile/lists surface with `view=map|list` (same pattern as Explore). Filter pins to the selected mark (`been` or `want`). **Never** may stay list-only. Logged-out users are sent to Explore to sign in (`GuestAuth` already has username/password login on `main`).

**Out:** booking, four-kind directory seed (already [[ops/tickets/PRD-016]] / [[ops/tickets/PRD-017]] plus the experience gap — do not expand here), PRD-012 one-tap, PRD-013 ME totals/export, map rewrite, Next.js/FastAPI.
