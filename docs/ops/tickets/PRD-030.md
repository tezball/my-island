# PRD-030 — Guest visited, next, and saved lists on map

## Outcome

A **signed-in Guest** can review **visited**, **next**, and **saved** VisitIntents on a **map or a list**. Same Spring catalog + Vite PWA. Reuse the existing VisitIntent API and Explore Leaflet map. `/lists` is that review, with a list/map toggle. **Saved** shows on the map the same way Visited and Next do. **Do not** implement [[ops/tickets/PRD-013]] as written (My Places counts, 32-county progress, CSV export).

## Notes

**2026-09-20 gap.** [[ops/tickets/PRD-015]] (#97) is on `main`: `VisitTicks` on Explore/detail, private `/lists` for been / want / never. Terry cannot see been/want on a **map**. That is this ticket, not a reopen of PRD-013.

**Reuse:** `GET`/`PUT`/`DELETE` VisitIntent under `/api/v1/me/…`, published Place coords, `MapView` (Leaflet + OSM). One VisitIntent per Guest + Place. Lists stay **private**. Public Place JSON stays an **anonymous visited count** only.

**UI:** signed-in profile/lists surface with `view=map|list` (same pattern as Explore). Filter pins to the selected mark. Logged-out users are sent to Explore to sign in (`GuestAuth` already has username/password login on `main`).

**2026-10-03:** The marks are **visited**, **next**, and **saved**. Saved shows on the map the same way Visited and Next do. The earlier “never may stay list-only” line is superseded. This ticket stays `review`.
