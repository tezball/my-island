# WF-039 — GIS origin_mismatch for Google Sign-In

## Outcome

Google Identity Services on the existing fishing-journals **Web** client no longer 400s with `origin_mismatch` because the PWA sent the wrong origin. Local compose GIS uses `http://localhost:5173` (not `127.0.0.1`). Mock-prod origins and the Google Cloud Console click for Terry are in [[ops/runbooks/GOOGLE_GIS]]. **Not** Spring OIDC ([[ops/tickets/WF-014]]). **No prod host.**

## Repro

Sign in with Google on Explore. Google: *You can't sign in to this app because it doesn't comply with Google's OAuth 2.0 policy. Register the JavaScript origin. Error 400: origin_mismatch.*

## Notes

GIS popup reads `window.location.origin`. The PWA does not (and must not) pass `login_uri` / a fake origin. House `./scripts/app start` opens `http://127.0.0.1:5173`; Google treats that as a different origin from `http://localhost:5173` and often rejects the IP even if registered.

Live Web client id (public in the PWA bundle): `664892630671-20micp7onoh8rceh0r1jonr0f1366j97`. Apex `https://fishing-journals.com` and `https://app.fishing-journals.com` still need to be on that client’s **Authorized JavaScript origins** — IdP console is a human step.

## Verify

- [x] PWA GIS `initialize` has no `origin` / `login_uri`; `127.0.0.1` canonicalizes to `localhost` before GIS
- [x] Local compose web gets `VITE_GOOGLE_CLIENT_ID` from `.env`
- [x] Runbook lists exact JS origins + Console location; no prod host
- [ ] Human: those origins saved on the Web client (IdP console)
