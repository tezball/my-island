# WF-052 — Dedicated Jenkins CI checkout directory

## Outcome

Multibranch Jenkins can create its host-visible checkout. The copy lives at `~/Projects/my-island-ci/<job>`, and the Jenkins service bind-mounts that directory only. It is not the primary clone and it is not all of `~/Projects`.

## Notes

Prepare on `main`, on `cursor/ireland-directory-program-3a04` (build 2, commit `b2858d7`), and on `cursor/prd-030-been-want-map-d362` failed before compile:

`mkdir: cannot create directory ‘/Users/tezball/Projects/my-island-ci-…’: Permission denied`

The container bind-mounts only `HOST_REPO` (`~/Projects/my-island`). Inside the container the parent is root-owned `755`, so `jenkins` cannot create a sibling. [[ops/tickets/WF-051]] stays the status/isolate ticket. This ticket is only the checkout directory.

The running container keeps the old mounts until it is recreated. Do that after the current publish-main turn, not during it:

```bash
mkdir -p ~/Projects/my-island-ci
docker compose up -d jenkins --force-recreate --no-deps
```

## Verify

- [ ] CI root is `$JENKINS_CI_ROOT/<job>`, default `$(dirname "$HOST_REPO")/my-island-ci/<job>`
- [ ] `compose.yml` bind-mounts that directory only, not `~/Projects`
- [ ] Prepare exits with a recreate hint when the parent is missing or not writable
- [ ] Runbook says the mount exists only after the Jenkins container is recreated
- [ ] `python3 -m pytest ops/tests -q -m "not stack"`
