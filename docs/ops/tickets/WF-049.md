# WF-049 — Cloud Agents trigger host Jenkins deploy

## Outcome

Deploy-on-main runs from a **self-hosted Cursor worker on the Mac mini** that already has host Jenkins + `MOCK_PROD_*` + the SSH key. That worker talks to **loopback Jenkins** (`deploy-mock-prod`). **Agents never SSH.** The VPS key stays in Jenkins. **Not** a GitHub Environment `production`. fishing-journals.com is mock-prod.

**Lock C (Terry 2026-09-20).** Do **not** pick **B** (Cloud Agent VMs reaching Jenkins over HTTPS). Do **not** pick **D** (GitHub Actions SSH deploy). Status-quo **A** (human starts laptop compose; cron only) is not the agent path.

[[ops/tickets/WF-042]] still owns MCP **status + trigger shape**. This ticket is **where** the trigger runs: the mini worker, not a Cloud VM.

## Notes

Git for [[ops/tickets/WF-040]] / [[ops/tickets/WF-048]] is done. Live still lags `main` because only **host** Jenkins has `MOCK_PROD_*`. Cloud-compose Jenkins is a different controller and must not get the VPS key.

Cloud VMs do not need a public Jenkins URL. Sessions that trigger deploy (and Jenkins MCP against host jobs) **land on the Mac mini worker**. They use MCP/HTTP to local Jenkins — not SSH, not GHA SSH.

Secrets stay in Jenkins / worker env. **Never in `docs/`.**

## Verify

- [ ] Self-hosted Cursor worker on the Mac mini can trigger `deploy-mock-prod` on **host** Jenkins (loopback / MCP)
- [ ] Cloud VMs do **not** require Jenkins HTTPS from the public internet (not B)
- [ ] No GHA SSH deploy; no GitHub `production` Environment (not D)
- [ ] SSH key never leaves Jenkins; agents never SSH
- [ ] Cloud VM compose Jenkins is **not** the deploy Jenkins
- [ ] After a worker trigger, public `/actuator/info` SHA can match `origin/main` when host Jenkins has `MOCK_PROD_*`
