# WF-017 — STACK-E2E MCP vs compose chaos drill skill and runbook

## Outcome

Agents can run the place-stub stack E2E drill from a skill + runbook without inventing curl: happy-path compose, HTTP create/list/get + actuators, MCP-or-HTTP observe, opt-in chaos overlay, write gaps. Chaos stays **out** of required CI.

## Notes

E2E workshop 2026-09-06 found the drill is **wired** but not **taught**:

- `./scripts/dev up` boots catalog **without** Spring profile `chaos`. Overlay is required: `docker compose -f compose.yml -f compose.chaos.yml --profile chaos up -d catalog --wait`.
- Architecture shorthand `docker compose --profile chaos up` **without** `compose.chaos.yml` leaves `SPRING_PROFILES_ACTIVE` unset — assaults never start.
- Chaos Monkey latency + exceptions fired on place HTTP (`RuntimeException: Chaos Monkey - RuntimeException` in logs). Spring default 500 JSON has **no** chaos marker in the body. `/actuator/chaosmonkey` is **404** (exposure is `health,info,prometheus` only).
- `restController` + `service` watchers together made ~70% 500s on list/get/create; `/actuator/health` stayed 200 and kill stayed off.
- “MCP vs compose” (STACK-E2E §7) is now [[ops/runbooks/STACK_E2E_PLACE_STUB]]. Follow [[ops/runbooks/ADD_SKILL]] for later skill edits.

Do not expand into full [[ops/tickets/PRD-001]]. Do not put chaos on the default compose service or CI `catalog` / `stack` jobs.

Id note: drafted as WF-016 on PR #30 before rebase onto `main` (WF-015 already taken by the spine strip). Renumbered to the next free id after [[ops/tickets/WF-016]].
