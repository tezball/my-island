# PRD-010 — Visitor auth (email + password)

## Outcome

A **Guest** can sign in with **username/password and Google SSO** (existing GIS). Same JDBC session either way. **Seed password Guests** so CI / Jenkins / Gatling / agents can log in without Google. **No OIDC stub.** GIS stays; do not make Google a blocker. VisitIntent ([[ops/tickets/PRD-015]]) requires a signed-in Guest — not this ticket’s UI.

## Notes

CEO 2026-09-19 override: this is **not** a live consumer app. Dual auth. GIS `POST /api/auth/google` already exists — keep it. Username/password is the automation path (seed accounts in compose/mock-prod env, **never** passwords in `docs/`). Spring redirect OIDC ([[ops/tickets/WF-014]]) stays later; not required for this slice.

**No OIDC stub.** Do not ship `/api/v1/auth/stub/oidc`. GIS is real Google Identity Services, not a stub IdP.

Stream 2 alongside VisitIntent; parallel with stream 1 ([[ops/tickets/WF-040]]). VisitIntent may use GIS today and password when this lands — do not serialize PRD-015 behind this ticket. Closing public Place writes is [[ops/tickets/WF-046]] — this ticket does not leave `POST /api/v1/places` open as the Guest write path.

**2026-09-20:** Username/password **login** form is on `main` (`GuestAuth` on Explore, shipped with [[ops/tickets/PRD-015]] #97). GIS login remains. **Leave this ticket `implement`** for leftover **signup / email verify / password reset / Mailpit**. Do not clone a second login ticket. Map/list of been/want is [[ops/tickets/PRD-030]], not auth.
