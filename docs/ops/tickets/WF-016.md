# WF-016 — Cloud Agent mcp-grafana and Postgres-RO against local compose

## Outcome

A Cloud Agent on this repo can **read** local compose Grafana + Postgres the same way a laptop Cursor session does: `mcp-grafana` PromQL/LogQL (`--disable-write`) and Postgres MCP `SELECT` only. HTTP to `127.0.0.1:3030` / `5433` already works on the VM; the gap is the **MCP toolbox**, not compose.

Does **not** close [[tickets/WF-004]] (staging/prod remote MCP) or [[tickets/WF-010]] (always-on EU staging). Those stay blocked until a shared env exists. This ticket is the workshop-shaped hole: Cloud Agent + local compose.

## Notes

E2E workshop 2026-09-06 (`ops/runs/e2e-place-stub-mcp-chaos-2026-09-06.md`):

- Catalog HTTP and Grafana/Prometheus HTTP succeeded from the Cloud VM.
- Agent dynamic MCP namespaces were GitHub, Gmail, Calendar, Drive, cursor-cloud — **no** `grafana`, **no** `postgres`.
- `.cursor/mcp.json` stdio (`uvx mcp-grafana`, `npx` Postgres → `ops` db) is not attached to Cloud Agent runs. `uvx` is on PATH.
- `ops_reader` can `SELECT` `mcp_ping` on db `ops`. `SELECT` on `catalog.place` is **permission denied**. Even after MCP is attached, listing-stub review cannot use Postgres-RO until catalog grants (or a second SELECT-only DSN).

Id note: this was drafted as WF-015 on PR #30 before the spine strip landed on `main` as [[tickets/WF-015]] (`done`). Renumbered to the next free id.

House: Grafana OSS + `mcp-grafana`, not Datadog. No secrets in notes.
