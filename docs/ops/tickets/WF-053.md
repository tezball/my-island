# WF-053 — Wait for catalog before the Jenkins zap scan

## Outcome

The Jenkins zap stage scans catalog only after the address it uses accepts `GET /api/v1/places`. On the controller that address is `http://catalog:8080`. `http://127.0.0.1:8081` stays the host publish used when compose DNS is absent.

## Notes

`./scripts/dev up` returns after the in-container healthcheck and the Grafana wait. Seed already talks to `catalog:8080` from the controller. The zap stage then ran `zap_style_scan.py http://127.0.0.1:8081` with no wait. That loopback port is not catalog inside the controller, so the scan got `Connection refused` while the host publish later showed healthy.

## Verify

- [ ] Zap waits until `${TARGET}/api/v1/places` answers before the scan
- [ ] Target is `http://catalog:8080` when that readiness URL answers, else `http://127.0.0.1:8081`
- [ ] `python3 -m pytest ops/tests -q -m "not stack"`
