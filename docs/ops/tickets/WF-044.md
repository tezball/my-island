# WF-044 — ZAP-style scanner in CI against local compose

## Outcome

A **ZAP-style** DAST scanner runs **in merge CI** (Jenkins + GHA) against **local compose and/or Testcontainers**, **every merge**. Do **not** move ZAP to cron. It is **not** the primary scan against public https://fishing-journals.com/. Keep the scanner **off** UI-less `unit` / `catalog` jobs (fast merge). Playwright stays off those jobs too ([[ops/tickets/WF-011]]).

## Notes

Security lock **B** + test-lanes lock (CEO 2026-09-19). Playwright is cron + MCP. Catalog API, Chaos Monkey, and ZAP are **on merge**. Gatling is trickle + weekly, not merge load. Implementer picks OWASP ZAP baseline / zap2docker / a documented equivalent — not a paid SaaS as system of record.

Target job-started catalog + PWA (or Testcontainers-bound URLs). Do not spider the public test server as the merge gate. Automerge `needs` includes this job once wired. After [[ops/tickets/WF-046]], an open `POST /api/v1/places` is a finding — not expected house behaviour.
