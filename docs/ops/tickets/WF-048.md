# WF-048 — Main CI after GITHUB_TOKEN squash-merge

## Outcome

A squash-merge to `main` by GHA `automerge` (`GITHUB_TOKEN`) still produces **check-runs on the `origin/main` SHA**. Jenkins `deploy-mock-prod` can then deploy VisitIntent / catalog to https://fishing-journals.com/. Agents never SSH. No GitHub Environment `production`.

## Notes

Reticketed from a colliding WF-047 — that id is the DX handbook on `main` (#99). This is the deploy-gate follow-up.

WF-040 gates deploy on GHA `unit` + `catalog` + `web` + `stack` for **`origin/main`**. Ready PRs squash-merge with `GITHUB_TOKEN`, which **does not fire `push` workflows**. After [[ops/tickets/PRD-015]] (#97) the squash SHA had **no** check-runs; the last `push` CI on `main` was 2026-09-06. Jenkins `H/5` skipped. Live stayed pre-VisitIntent: `/actuator/info` HTML, anonymous Place POST 201, no `beenCount`, no `/api/auth/login`.

**Fix:** `workflow_dispatch` CI on `main` after squash (GITHUB_TOKEN **may** dispatch). Gate also treats a **merged associated PR** head’s green checks as enough when the squash SHA has only missing/pending checks (not failures). Jenkins runs the gate script from `origin/main` so HOST_REPO lag does not keep the old skip forever.

## Verify

- [ ] `.github/workflows/ci.yml` has `workflow_dispatch`
- [ ] `automerge` has `actions: write` and `createWorkflowDispatch` on `main` after squash
- [ ] `gate_mock_prod_deploy.py` falls back to merged PR head checks when the squash SHA’s required checks are missing/pending
- [ ] `python3 -m pytest ops/tests -q -m "not stack"`
- [ ] No agent SSH; no `gh pr merge`; no production Environment
