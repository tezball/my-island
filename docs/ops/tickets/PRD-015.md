# PRD-015 — VisitIntent visited, next, saved

## Outcome

A **Guest** can browse the Ireland **Place** list, **sign in** (username/password **or** Google SSO), set one **VisitIntent** per Place, and see those three **private** lists. The words are **Visited**, **Next**, and **Saved** (`visited`, `next`, `saved`) in the screen, the API, and the database. **Saved** is an explicit mark, not every other place. Signing in is required to tick; anyone can browse. The public count is the **visited count** only (no PII). **Next** and **Saved** stay private to the Guest. All three can show on the map. Same Spring catalog + Vite PWA + PostGIS. **Do not** implement [[ops/tickets/PRD-012]] / [[ops/tickets/PRD-013]] as one-tap check-off / My Places. Do not add multiple named trips.

**Privacy:** Guest lists are **private** (session only; not another Guest’s marks). **Public counts lock A:** Place API/UI expose an **anonymous visited count** only (integer, no names, ids, or other PII). **Next** and **Saved** stay private to the Guest — not on Place pages, not in public Place JSON.

**Out of this slice:** campsite / B&B / experience booking, one-mock-per-county listings, map rewrite, Datadog/Next/FastAPI, a second API service.
