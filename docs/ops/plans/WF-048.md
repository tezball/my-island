# Plan: Main CI after GITHUB_TOKEN squash-merge

## Outcome

Jenkins `deploy-mock-prod` sees green GHA checks for `origin/main` after Actions squash-merge, so fishing-journals.com can track VisitIntent. Done when automerge dispatches CI on `main` and the deploy gate accepts merged-PR checks when the squash SHA has no push runs.

## Out of scope

- SSH / running `deploy-mock-prod.sh` from a cloud agent
- Changing VisitIntent product behavior (local compose already matches PRD-015)
- A GitHub Environment named `production`
- Overwriting [[ops/tickets/WF-047]] (DX handbook on `main` via #99)

## Steps

1. Add `workflow_dispatch` to GHA CI. After squash, `automerge` dispatches that workflow on `main` (`actions: write`). GITHUB_TOKEN cannot fire `push`; it **can** fire `workflow_dispatch`.
2. Gate: if required checks on `origin/main` are missing/pending (not failed), load merged associated PR head SHA (`GET /commits/{sha}/pulls`) and use those check-runs.
3. Jenkins job: `git fetch origin main` then run `origin/main`’s `gate_mock_prod_deploy.py` so a stale HOST_REPO still picks up this gate.
4. Vault + unit tests. No secrets in notes.
