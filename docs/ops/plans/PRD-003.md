# Plan: Vite+React PWA — Explore list and map

## Outcome

A **phone-first Vite + React + TypeScript PWA** in **`web/`** that is the visitor **Explore** surface: scrollable list + map as equal peers, shared filters, search, distance sort, clusters, map/list toggle, near-me with a permission fallback. The SPA talks **only** to the Spring catalog at `http://127.0.0.1:8081` (`GET /api/v1/places`, `GET /api/v1/categories`, `GET /api/v1/counties`). **Done when** a follow-up implement PR (this planning change has **no application code**) renders Explore against local compose, the verify list below is checkable, and WCAG 2.2 AA holds on Explore.

Public brand is **OPEN**. User-facing copy is “Explore” / “Places” / Ireland directory — never StayÉire, Halfdoor, or Inis.

**Human gate:** do not scaffold Vite until this ticket is `implement` (or this plan `approved`).

## Catalog contract (landed, host `:8081`)

Spring owns the API. Explore is a thin SPA. **Dev:** Vite `server.proxy` `/api` → `http://127.0.0.1:8081` (compose service name `catalog:8080` when the Vite process is on the compose network). That proxy is **not** a BFF. **Do not** add catalog CORS unless staging serves the PWA from a different origin; prefer same-origin `/api` via the proxy or a later nginx/caddy sidecar (host pick still open).

| Method | Path | Explore use |
|---|---|---|
| `GET` | `/api/v1/places?published=true` | Directory. **Always** `published=true` so PRD-008 drafts stay hidden |
| `GET` | `/api/v1/places?categoryId=&countyId=&published=` | Optional server-side single-category / single-county; see gaps |
| `GET` | `/api/v1/categories` | Filter chips (`poi`, `experience`, `campsite`, `bnb` + labels) |
| `GET` | `/api/v1/counties` | 32 counties incl. NI (`ni`, `countryCode`) |
| `GET` | `/api/v1/places/{idOrSlug}` | **Not** required for Explore list/map (PRD-011) |
| `POST` | `/api/v1/places` | **Forbidden** from the PWA |

`PlaceResponse` (camelCase JSON): `id`, `slug`, `name`, `description`, `category: {id,label}`, `county: {id,name}`, `town`, `latitude`, `longitude`, `published`, `partnerId`, `priceBand`, `website`, `phone`, `facilities: string[]` (ids), provenance fields unused here.

**No images on Place.** DIR-01 photo: category-coloured placeholder tile (not a stock photo CDN). Real photos wait on [[ops/tickets/PRD-002]] / [[ops/tickets/PRD-011]].

**No `GET /api/v1/facilities`.** DIR-13 chips use the Flyway MVP set (`parking`, `toilets`, `dog_friendly`, `accessible` — `V3__facility.sql`). Optional cheap catalog `GET /api/v1/facilities` in the implement PR is OK; do not hard-code a closed Java enum.

## Gaps vs DIR-* / MAP-* (client-side first slice)

Today’s list is `categoryId` **or** `countyId` (singles), `order by name`, no `q`, no bbox, no distance, no facility query. Seed size is small. **First slice: one `GET …/places?published=true`, then filter / search / sort / bbox in the SPA.** Do not invent a TypeScript API.

If that fetch is too large before launch, a **thin Spring expand on the implement PR** (same house, not a second service) may add repeatable `categoryId` / `facilityId`, `q`, `bbox`, `nearLat`/`nearLon`+`sort=distance`. Only if client-side is clearly not enough. Empty directory is OK while seed is draft.

## Screen (phone-first)

One route: `/` (Explore). **No** `/places/:slug`, `/me`, `/login`. Bottom chrome is **Map | List** toggle (not a three-tab product bar). Leave a comment seam for later tabs; do not ship fake My Places / Account destinations.

- Primary actions in the **bottom third**. Filters as a bottom sheet, not a top modal.
- Map and list share one filter state: `view`, `category` (csv), `county` (csv), `facility` (csv), `q`. **Do not** put the user’s lat/lon in the URL (NFR-06 adjacent).
- Near-me: `navigator.geolocation`. Granted → centre map + distance on cards + distance sort. Denied / unavailable / insecure context → Ireland overview (~53.4, −8.2, zoom ~6), hide distance, name sort, copy that near-me is off.
- Tap card or pin: **bottom sheet only**. “Open place” is a disabled control or omitted until PRD-011.
- Desktop: wider list beside map is OK; phone is the design target.
- Copy: no StayÉire / Halfdoor / Inis. No “my-island” on the customer surface.

**Map:** MapLibre GL JS, OSM (or Carto) raster — **no Mapbox token**. Lazy-load the map module so the list can paint first (NFR-01, mid-range Android / 4G). Cluster at low zoom; category colour + icon on expanded pins.

**PWA:** `vite-plugin-pwa` (Workbox). Web app manifest + icons + splash. Installable on iOS/Android. Offline **shell** renders before network; DIR-11 caches catalog GETs. Explore target: interactive <2.5s.

**A11y:** WCAG 2.2 AA on Explore — contrast, labels, 44px targets, keyboard filters, screen-reader list as the map alternative (NFR-04). No hover-only actions.
