# Plan: Mock-prod info probe (version + git hash)

## Outcome

Deploy CI can prove the **exact git SHA** is serving at https://fishing-journals.com/. Caddy proxies `/actuator/health` and `/actuator/info`. Info is catalog JSON (`app.version`, `app.gitCommit`, …). `deploy-mock-prod.sh` fails on HTML, `unknown`, or a SHA mismatch. Health UP on a stale process is not enough.

## Out of scope

- GitHub Environment `production`
- Public `/actuator/prometheus`
- Stamping the PWA with its own version file

## Steps

1. Caddy apex + `app.`: proxy health **and** info to `island-catalog`.
2. Bake `GIT_COMMIT` / version / build time into the catalog image; expose via Spring `info.app.*`.
3. Verifier script: public info must match the SHA about to be (or just) deployed.
4. Deploy script writes those values into `.env.mock-prod`, force-recreates catalog, then checks public info.

## Verify

- [ ] Caddy fixture contains `/actuator/info` → `island-catalog`
- [ ] Catalog test: `/actuator/info` JSON shape
- [ ] Verifier rejects SPA HTML, `unknown`, and wrong SHA
- [ ] Deploy script calls the verifier against the public origin

Implement bar (company draft): [[ops/workflow/DOD]] — outcome, automated proof for the risk, CI-runnable, no nits-as-blockers.

## MCP / env

Local compose optional for catalog tests (Testcontainers). Mock-prod SSH only when running the deploy script.
