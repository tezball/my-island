# Plan: Cloud Agents trigger host Jenkins deploy

## Outcome

A **self-hosted Cursor worker on the Mac mini** (the box that already has host Jenkins + `MOCK_PROD_*` + the SSH key) can trigger `deploy-mock-prod` so fishing-journals.com tracks green `main`. Agents never SSH. The VPS key stays in Jenkins. No GitHub Environment `production`.

**Lock C (Terry 2026-09-20).** Do not implement B or D.

[[ops/tickets/WF-042]] already names the MCP/HTTP trigger. This plan is **where** that trigger runs.

## Out of scope

- **B** — Cloud Agent VMs reaching host Jenkins over HTTPS (token in cloud secrets)
- **D** — GitHub Actions SSH deploy; key in GitHub secrets
- SSH from agents or chat
- GitHub Environment `production`, `compose.prod`, prod SSH
- Putting `MOCK_PROD_*` or the VPS key in `docs/`, tickets, or Cloud Agent chat
- Treating Cloud Agent compose Jenkins as host Jenkins
- Replacing [[ops/tickets/WF-042]] MCP pack work
- Changing automerge / [[ops/tickets/WF-048]] dispatch (git already done)

## Steps (lock C)

1. Confirm **host** Jenkins on the Mac mini has `MOCK_PROD_*` and can run `deploy-mock-prod`. Fail closed if missing.
2. Run a **self-hosted Cursor worker** on that mini. Label it so deploy-trigger / Jenkins-MCP sessions land there. Do not put the worker token or host IPs in `docs/`.
3. From that worker: MCP or Jenkins HTTP to **loopback** (`127.0.0.1:8085`) — status + `deploy-mock-prod` trigger only. Agents never SSH; they never run `./scripts/deploy-mock-prod.sh`.
4. Cloud VM agents keep public HTTPS to fishing-journals.com (health/info/places). They do **not** need Jenkins on the internet.
5. Prove: session on the mini worker triggers the job → `ops/scripts/smoke_mock_prod.py` / public info SHA matches `origin/main`.
6. Note in [[ops/workflow/DX]] / [[ops/runbooks/MOCK_PROD_DEPLOY]]: deploy-on-main trigger is the mini worker, not cloud HTTPS to Jenkins, not GHA SSH.
