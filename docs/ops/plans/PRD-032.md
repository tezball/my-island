# Plan: Listing kinds on the map

## Outcome

Explore (list and Leaflet map) shows published Ireland places of kind `poi`, `experience`, `campsite`, `bnb`, and `supplier`. Done when a phone can filter to each kind and open one real listing of each. No checkout.

## Out of scope

- Checkout, calendars, mock PSP, per-county booking seed ([[ops/tickets/PRD-016]]–[[ops/tickets/PRD-029]] stay `inbox`)
- A second been/want journey ([[ops/tickets/PRD-030]] already covers that)
- Host draft forms ([[ops/tickets/PRD-033]])
- Next.js, FastAPI, a second API, a new database
- GitHub Environment `production`, `compose.prod`, prod SSH
- Scraping another marketplace

## Steps

1. Keep category as data ([[ops/runbooks/LISTING_ROLLOUT]], [[ops/data/listing-types]]). If Java or TypeScript uses a closed enum, that is a bug — store the kind as data.
2. `supplier` is already named in the listing-types note. Ship it in Flyway (reference row or equivalent data), not a new service.
3. Seed at least one published campsite, one B&B, one experience, and one supplier in Ireland. Licensed or clearly attributed photos. Do not replace the existing POIs.
4. Explore filters and map pins use the category field. One Explore page. Phone-first chips.
5. Place detail renders each kind (name, county, map, how to visit or contact).
6. After the PR merges, deploy with the existing mock-prod path (Jenkins `deploy-mock-prod` from `main`, Mac mini worker, decision 37). Confirm on https://fishing-journals.com: info `gitCommit` matches that `main`, and `GET /api/v1/places?published=true` includes the new kinds. Agents never SSH. This planner does not deploy.
