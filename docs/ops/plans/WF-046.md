# Plan: Close public Place writes; seed/import only

## Outcome

Public catalog HTTP does **not** accept Place `POST` / `PUT` / `PATCH` / `DELETE`. The open `POST /api/v1/places` closes. Places enter the database through **seed/import in CI/deploy**. Signed-in Guests write **VisitIntent only**. Directory GETs stay public.

## Out of scope

- A curator admin UI or privileged public Place CRUD
- Reopening [[ops/tickets/PRD-012]] / [[ops/tickets/PRD-013]] as Place writes
- Changing Ireland seed content
- Moving seed/import onto fishing-journals.com as an anonymous HTTP POST
- Chat `gh pr merge`

## Steps

1. Spring Security: deny Place collection/item writes for anonymous and Guest sessions. Keep GET list/detail (and auth/health/info) as they are today. Close `permitAll()` on `POST /api/v1/places`.
2. Replace catalog contract create-via-public-POST with: SQL/Flyway/test-seed for Place rows **plus** Gherkin that anonymous POST/PUT/PATCH/DELETE is 401/403. Do not leave `CatalogTest.createListGetPlace` as proof of a public write.
3. Document CI/deploy as the only Place write path: existing Flyway + `import_leads.py` / deploy seed. If a script still POSTs HTTP, point it at loopback in the job network **or** switch it to SQL — never Caddy-public.
4. Align [[ops/tickets/PRD-015]]: Guest writes are VisitIntent under `/api/v1/me/…` only. Do not copy the old permitAll pattern.
5. Note on [[ops/tickets/WF-044]]: ZAP/DAST should not treat an open Place POST as expected. Workshop STACK-E2E POST history stays; live policy is this ticket.
