# Plan: House Prometheus and Loki from the test server

## Outcome

**Source of truth** is the test server (fishing-journals.com): catalog `/actuator/prometheus` and structured logs land in house Prometheus and Loki. Cloud Agents query them via **Grafana MCP HTTP/SSE** (`--disable-write`). Laptop Grafana uses a **script/tunnel to those same datasources**. Done when an agent’s PromQL/LogQL is mock-prod, not “whatever is on 127.0.0.1:9091 from local compose.” Prometheus stays private.

## Out of scope

- Leaving agents on local-compose-only metrics as the house observe path
- Publishing Prometheus (or Loki push) on the public internet
- Treating `grafana.fishing-journals.com` as house Grafana
- Closing [[ops/tickets/WF-004]] / [[ops/tickets/WF-010]]
- Datadog / New Relic as system of record
- Agent SSH (laptop/Jenkins tunnel script is allowed; agents use MCP/HTTP)

## Steps

1. Ingest **test-server** catalog metrics into house Prometheus (private scrape, SSH-from-Jenkins, or authenticated `remote_write` — implementer pick). Do **not** expose `:9090`/`:9091` on the public host.
2. Ship **test-server** catalog logs into house Loki (Promtail/Alloy/Loki4j — pick). Loki today has no app labels.
3. Repo script so **laptop Grafana** datasources are those Prom/Loki (tunnel or remote URL). Same data the agent MCP sees. Local compose scrape of `catalog:8080` is no longer the agent/laptop SoR.
4. Grafana MCP **HTTP/SSE** for Cloud Agents: `mcp-grafana --disable-write`, `GRAFANA_URL` reachable by Cursor’s MCP proxy (not `127.0.0.1` as the Cursor-backend target). Viewer token in MCP settings, never `docs/`.
5. Document in [[ops/workflow/MCP]]: WF-016 loopback PromQL remains a **compose workshop fallback**; house observe after this ticket is test-server data via MCP.
