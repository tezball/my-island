# Plan: Support self-serve and role homes

## Outcome

Guest, host, supplier, curator/admin, and support are roles a person can take without an engineer. Each role has a phone-first home. Support’s home includes a help path that unblocks the common tasks (sign in, tick a place, submit a draft).

## Out of scope

- Booking help policies and the booking support inbox ([[ops/tickets/PRD-028]], [[ops/tickets/PRD-029]] stay `inbox`)
- Checkout, disputes, payouts
- A second identity provider (Spring redirect OIDC stays [[ops/tickets/WF-014]])
- Staffing a human support team in this ticket
- GitHub Environment `production`, `compose.prod`, prod SSH

## Steps

1. Roles live on the existing account. Self-serve: the signed-in person chooses guest, host, supplier, or asks for curator/admin or support through an in-app path that does not require an engineer to edit the database by hand. Curator/admin may stay a promoted flag if self-serve signup of admin would be unsafe — the help path must say how promotion works without filing an engineering ticket. Support is a real role, not a mailto link to the company.
2. Homes: guest → journey ([[ops/tickets/PRD-030]]); host → their drafts; supplier → their drafts; curator → unpublished queue; support → the help path plus enough context to answer those tasks.
3. Help content is vault-free in the app (short pages in the PWA). Cover sign-in, ticking been, and draft submit. No secrets.
4. After merge, mock-prod deploy from `main`. Confirm on https://fishing-journals.com that each home renders for a matching session and the help path is reachable logged out and logged in. Agents never SSH.
