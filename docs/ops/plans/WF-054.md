# Plan: Automate review, CI fix, and comment fix on every PR

## Outcome

One Cursor automation, **my-island PR loop**, covers review, failed GitHub Actions, and review comments. GitHub Actions keeps testing (`ci.yml`) and squash-merge (`automerge.yml`, [[ops/tickets/WF-050]]). The agent does not merge and does not approve as `github-actions[bot]`.

Done when [[ops/workflow/PR-LOOP]] is on `main` and the automation row is Enabled with the triggers in that note. This session can land the note and the prompt. It cannot Save the dashboard row.

## Out of scope

- A second merge policy, `createReview` from `GITHUB_TOKEN`, or merging drafts and forks
- Re-running `unit tests` / `catalog tests` / `web tests` / `compose stack` on a schedule in `ci.yml`
- Treating a Jenkins commit status (including `compose stack` or `continuous-integration/jenkins/branch`) as a failed required check
- Slack, Jenkins job edits, product UI
- Disabling the existing PR Review automation (`2a5248fd-aedf-11f1-bf4b-42ffb4d10ea7`)

## Steps

1. Write [[ops/workflow/PR-LOOP]] (the loop, the caps, the paste-ready prompt) and point [[ops/workflow/AUTOMATIONS]] and [[ops/workflow/CI]] at it.
2. Add `.cursor/skills/pr-loop/SKILL.md` so an agent session follows the same order.
3. Human: [cursor.com/automations](https://cursor.com/automations) → new automation `my-island PR loop` → triggers and tools in [[ops/workflow/PR-LOOP]] → paste the prompt → Save → Activate. Paste the dashboard URL (UUID only) on the ticket.

## Verify

- [ ] Prompt says the agent never `gh pr merge` and never pushes `main`
- [ ] Failed CI means Actions check-runs, not Jenkins statuses
- [ ] `python3 -m pytest ops/tests/test_pr_loop.py ops/tests -q -m "not stack"`
