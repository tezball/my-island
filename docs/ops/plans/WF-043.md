# Plan: Chaos Monkey in CI for retries and fallbacks

## Outcome

A dedicated Jenkins + GHA **chaos** job on **merge** (house `compose.chaos.yml` overlay and/or catalog Testcontainers with Spring profile `chaos`) proves **retries and default fallbacks**. Automerge waits on it. `unit` / `catalog` stay chaos-off (fast UI-less jobs). Do **not** move Chaos Monkey to cron. Chaos Monkey is **not** a post-deploy assault on https://fishing-journals.com/. MCP `/stack-e2e` remains an optional drill.

- Enabling chaos inside default `unit` / `catalog` / `web` job bodies
- Playwright on those UI-less jobs ([[ops/tickets/WF-011]] is cron + MCP only)
- Moving this job to cron / scheduled-only CI
- Chaos Monkey against public fishing-journals.com on every [[ops/tickets/WF-040]] deploy
- kill-application, disk wipe, dropping the git checkout
- Replacing Gherkin/Testcontainers contract tests
- Closing [[ops/tickets/WF-017]] (already done)

## Steps

1. Add a **separate** GHA job and Jenkinsfile stage (not a profile on existing `catalog`). Dual-run. Wire automerge `needs` to include it.
2. Drive assaults with house overlay (`compose.yml` + `compose.chaos.yml` `--profile chaos`) and/or a Testcontainers catalog with `chaos,chaos-monkey`. Kill stays off.
3. Assert **retries and default fallbacks**. Do not re-assert create/list/get Gherkin.
4. Keep `./scripts/dev up` and `unit`/`catalog` free of `compose.chaos.yml`.
5. Document: merge CI is the required chaos lane; do not move to cron; MCP may trigger a drill later; deploy must not start Chaos Monkey on the public host.
6. Chat agents still do not `gh pr merge`.
