# Plan: Visitor auth (Spring Security + OIDC)

## Outcome

Visitors can create and keep an **Explorer** account (`ACC-01`–`ACC-09` in [`product/MVP.md`](../../product/MVP.md) §4): email+password, Google or Apple (real providers after [[ops/tickets/WF-014]]; local/test stub until then), email verify, session that survives a phone PWA relaunch, password reset, display name, email prefs (marketing **off** by default), account JSON export, and account delete. Identity lives in the existing **Java / Spring Boot** catalog process (`services/catalog`). Done when an implementer PR (separate session, ticket `implement`) proves the HTTP + unit checks in Verify, documents the check-off migrate contract below for [[ops/tickets/PRD-012]], and does not put secrets in git.

This planning PR contains **no application code**. Human sets [[ops/tickets/PRD-010]] to `implement` after reading this plan.

## Schema (Flyway expand)

PRD-001 deferred User. Add identity tables in catalog Flyway (next version after V6). **Do not** add a FK from `visit.user_id` to the user table in this ticket. Visit remains `user_id UUID` with **no FK** (PRD-001 contract). PRD-012 owns visit writes and any later FK.

Suggested names (`user` is reserved — table `app_user`, JSON still `user` / `me`):

```
app_user
  id uuid PK
  email citext UNIQUE NOT NULL
  password_hash text NULL          -- null = OIDC-only
  display_name text
  email_verified boolean NOT NULL DEFAULT false
  role text NOT NULL DEFAULT 'explorer'
    CHECK (role IN ('explorer', 'curator', 'admin'))
  marketing_email boolean NOT NULL DEFAULT false   -- ACC-09; off by default
  created_at timestamptz NOT NULL
  updated_at timestamptz NOT NULL
  deleted_at timestamptz NULL      -- delete seam; hard cascade visits is PRD-012/014

user_identity
  id uuid PK
  user_id uuid NOT NULL REFERENCES app_user (id)
  issuer text NOT NULL             -- 'password' | 'google' | 'apple' | 'stub'
  subject text NOT NULL
  UNIQUE (issuer, subject)

email_token
  id uuid PK
  user_id uuid NOT NULL REFERENCES app_user (id)
  purpose text NOT NULL            -- 'verify' | 'reset'
  token_hash text NOT NULL         -- store hash only
  expires_at timestamptz NOT NULL
  used_at timestamptz NULL
```

Spring Session JDBC tables from the Spring Session schema (expand-only). Role `curator`/`admin` exist as data for ADM-03 later; this ticket never grants them via API. Default signup role is `explorer`. Unauthenticated people are Visitors (no row).

## HTTP contract (catalog, camelCase JSON)

Keep `/api/v1` like places. Cookie session: `Set-Cookie` after signup/login/OIDC callback. SPA sends `credentials: 'include'`. Local PWA should **proxy** `/api` (and OAuth callbacks) to `:8081` so the cookie is same-origin ([[ops/tickets/PRD-003]] pairing). Cross-origin Vite without proxy needs CORS + `Allow-Credentials` on the catalog origin list (localhost only in local profile).

CSRF: cookie `XSRF-TOKEN` (not HttpOnly) + header `X-XSRF-TOKEN` on mutating calls. Document for the PWA. Do not disable CSRF in non-test profiles.

| Method | Path | Auth | Behaviour |
|---|---|---|---|
| GET | `/api/v1/auth/providers` | anon | `{ password: true, google: "live"\|"stub", apple: "live"\|"stub" }` |
| POST | `/api/v1/auth/signup` | anon | `{ email, password, displayName? }` → 201 + session. Send verify mail. Link identity `password`. Rate-limited |
| POST | `/api/v1/auth/login` | anon | `{ email, password }` → 200 + session. 401 on bad creds. Rate-limited |
| POST | `/api/v1/auth/logout` | session | Invalidate session |
| GET | `/oauth2/authorization/{google\|apple\|stub}` | anon | Spring OAuth2 start. Stub only if `APP_AUTH_STUB_OIDC=true` |
| GET | `/login/oauth2/code/{registration}` | anon | Callback → session. Email from IdP claims; create or **link** `app_user` by verified email |
| GET | `/api/v1/me` | session | `{ id, email, displayName, emailVerified, role, marketingEmail, providers[] }` |
| PATCH | `/api/v1/me` | session | `{ displayName?, marketingEmail? }` ACC-06 / ACC-09 |
| POST | `/api/v1/auth/verify/resend` | session | New verify token; Mailpit locally |
| GET | `/api/v1/auth/verify` | anon | `?token=` (raw token once; hashed at rest) → mark `email_verified` |
| POST | `/api/v1/auth/password/forgot` | anon | `{ email }` always 204 (no account oracle). Mail if user exists |
| POST | `/api/v1/auth/password/reset` | anon | `{ token, password }` |
| GET | `/api/v1/me/export` | session | JSON: account + identities (no hashes) + `visits: []` placeholder. PRD-012 fills visits. ACC-07 seam |
| DELETE | `/api/v1/me` | session | ACC-08 seam: tombstone/delete `app_user` + identities + tokens + sessions. **Do not** `DELETE FROM visit` here — emit a documented hook PRD-012 implements (`user.deleted`, `userId`) |
| POST | `/api/v1/auth/stub/oidc` | anon, **local/test only** | `{ email, displayName? }` → session as if Google/Apple succeeded. 404 when stub off |

Unauthenticated `GET /api/v1/me` → 401. Negative tests required (NFR-13 for these routes).

Password rules: min 10 characters; BCrypt. Display name: 1–40 chars, optional at signup (default: OIDC `name` or email local-part).

**Email verify is not a gate for check-off migrate.** Session is valid immediately after signup so CHK-02 can run. Verify is still required (ACC-03): send mail, surface `emailVerified` on `/me`, block *email change* (if added) until verified. Transactional mail cannot be unsubscribed (ACC-09 is marketing + product news).

## Pre-signup check-off migrate contract (for PRD-012)

CHK-02: ticks before account live **only on the device**; on signup they become the Explorer’s visits **without loss or duplication**. Server cannot read IndexedDB. Auth’s job is a stable user id + a live session. Visits stay PRD-012.

**Visit schema of record** (PRD-001 / MVP §5): `visit.id`, `visit.user_id` (**UUID, no FK**), `place_id`, `visit_type` (`VISITED` \| `STAYED`), `occurred_on` nullable, `date_precision` (`DAY` \| `MONTH` \| `YEAR` \| `UNKNOWN`), private `note`, `created_at`, `synced_at`. PRD-010 does not insert visit rows and does not add the FK.

### Client (PWA — PRD-003 storage, PRD-012 migrate call)

Anonymous ticks, keyed by `placeId`, each with:

```
clientTickId   uuid   (generated at tap; idempotency key)
placeId        uuid
visitType      VISITED | STAYED
occurredOn     date | null
datePrecision  DAY | MONTH | YEAR | UNKNOWN
note           string | null
tickedAt       instant
```

After **any** successful signup, password login, or OIDC login (including stub):

1. `GET /api/v1/me` → `id` is the `user_id` to persist.
2. `POST /api/v1/me/visits/migrate` **(PRD-012 implements; 404 until then is OK)** with `{ ticks: [ ... ] }` and the session cookie.
3. On 200, mark those `placeId`s migrated locally (or clear them). Retry is safe (idempotent).
4. Do not POST migrate until `/me` succeeds. Do not create a second user for the same email (OIDC link-by-email above).

### Server (PRD-012)

| Rule | Behaviour |
|---|---|
| Auth | Session required; `user_id` = `/me.id`. Ignore any client-supplied user id |
| Unique | At most **one** visit row per `(user_id, place_id)` in MVP |
| Idempotency | Also unique on `clientTickId` when stored (nullable column OK). Retry does not duplicate |
| Conflict | If a row already exists for that user+place: **keep the server row** (first write wins). Count as `skipped`. Do not merge notes in MVP |
| Types | Persist `visitType` and `datePrecision` as given; do not invent `occurredOn` when precision is `UNKNOWN` |
| Response | `{ created: n, skipped: n }` |
| Privacy | Visits stay private (CHK-07). No public profile |

PRD-010 implementer **must not** ship a fake visit insert to “complete” migrate. A comment + 404 on `/api/v1/me/visits/migrate` until PRD-012 is correct. Tests in this ticket only assert `/me.id` is a UUID that can be stored as `visit.user_id`.

## Session on the phone (ACC-04)

- Cookie: HttpOnly, `Secure` in non-local, `SameSite=Lax`, path `/`, Spring Session JDBC.
- Idle/max: **30 days** (remember-me or session timeout — pick one persistent mechanism, not a 30-minute servlet default).
- PWA installed to home screen must send the cookie on same-origin API calls (Vite proxy / reverse proxy in front of catalog).
- Logout clears the session row.

## Rate limit (NFR-12 seam)

In-process limiter on `/api/v1/auth/signup`, `/login`, `/password/forgot`, `/stub/oidc` (e.g. Bucket4j or a small filter). No Redis. Limits may be loose locally. Do not rate-limit Actuator or public GET places in this ticket.

## Local / CI IdP stub

Default `./scripts/dev up` must **not** require Google, Apple, or a Keycloak container.

1. `APP_AUTH_STUB_OIDC=true` in local compose + `@SpringBootTest` (or profile `local`/`test`).
2. `POST /api/v1/auth/stub/oidc` establishes the same session shape as a live OIDC callback.
3. `GET /api/v1/auth/providers` shows `google`/`apple` as `"stub"` when registrations are unset.
4. Catalog tests: password signup/login, stub OIDC, `/me`, 401 without cookie, anonymous `GET /api/v1/places` still 200, Actuator still anonymous.
5. Optional Testcontainers OIDC **later** — not required to close this ticket.

## WF-014 hand-off (no secrets)

When a human picks a GDPR-friendly provider, they set **env names only** (values in a secret manager / compose env, never in `ops/` notes):

- `SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_ID`
- `SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_SECRET`
- `SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_APPLE_CLIENT_ID`
- `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` (PKCS8 via env, not a committed `.p8`)

Redirect URI pattern (document in WF-014 runbook; do not invent production hosts here):

- `{api-origin}/login/oauth2/code/google`
- `{api-origin}/login/oauth2/code/apple`

Local `{api-origin}` is `http://127.0.0.1:8081` (or the Vite-proxied origin). Staging URLs wait on WF-010. After console setup, agents only edit Spring config / env wiring.

## Steps

1. **Dependencies** — `spring-boot-starter-security`, `oauth2-client`, `spring-session-jdbc`. No Stripe. No second Maven module unless catalog tests become unmaintainable (default: same module).
2. **Flyway** — `app_user`, `user_identity`, `email_token`, Spring Session tables. Expand only. No visit FK.
3. **Security filter chain** — permit GET catalog lookups + Actuator `health`/`info`/`prometheus`; authenticate `/api/v1/me/**` and auth mutating routes; keep `POST /api/v1/places` open this ticket (document). CSRF cookie for SPA. CORS only for configured local origins.
4. **Password + session** — signup/login/logout/me/patch as in the table. BCrypt. JDBC session 30 days.
5. **Mail** — add Mailpit to root `compose.yml` (SMTP 1025, UI on a free host port). Verify + reset templates. Forgot-password is 204 always.
6. **OIDC** — optional Google/Apple registrations; stub path when env unset. Link-by-email so migrate does not fork users.
7. **Export / delete seams** — `/me/export` JSON; `DELETE /me` tombstone + session kill; visit cleanup hook documented for PRD-012/014.
8. **Tests** — Testcontainers PostGIS (existing `CatalogTest` style). Do not add Playwright (WF-011). Do not fail CI if Google secrets are absent.
9. **Observability** — structured logs on auth success/fail (`userId` after login, never password or tokens). Existing Prometheus scrape stays anonymous.
