# Plan: Visitor auth — username/password and Google SSO

## Outcome

Guests sign in with **username/password and Google SSO**. GIS stays (`POST /api/auth/google`). Password signup/login lands in `services/catalog` with the same JDBC session. **Seed password Guests** for the commit→deploy→test→confirm loop (Gatling, Playwright, agents). **No OIDC stub.**

**Done when** password + GIS both produce `/api/v1/me`, seed Guests exist in compose/mock-prod via env (not git), anonymous Place GETs still work, and secrets never land in `docs/ops/`.

## Out of scope (MVP)

- OIDC stub endpoints (`/api/v1/auth/stub/oidc`, stub IdP containers)
- Spring `/oauth2/authorization/google` ([[ops/tickets/WF-014]] — later)
- Implementing VisitIntent ([[ops/tickets/PRD-015]])
- Implementing [[ops/tickets/PRD-012]] migrate
- Implementing Place write lockdown ([[ops/tickets/WF-046]] owns closing `POST /api/v1/places`)

## House picks

| Item | Pick |

## HTTP (MVP)

Keep GIS. Add password:

| Method | Path | Auth |
|---|---|---|

PWA: username/password form **and** the existing Google button. One Guest per browser.
