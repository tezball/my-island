# Plan: GIS origin_mismatch for Google Sign-In

## Outcome

GIS Error 400 `origin_mismatch` is not caused by the PWA inventing an origin. Local GIS uses `http://localhost:5173`. Terry has an exact Google Cloud Console list for the existing fishing-journals Web client. No Spring OIDC. No prod host.

## Out of scope

- Spring `/oauth2/authorization/google` ([[ops/tickets/WF-014]])
- Password auth ([[ops/tickets/PRD-010]])
- Apple Sign-In ([[ops/tickets/WF-033]])
- Registering Cloud Agent preview URLs or a production host
- Clicking Google Cloud Console from an agent (IdP credentials)

## Steps

1. Stop passing anything GIS could treat as a redirect origin (`login_uri`). Keep `ux_mode: popup` + ID token `POST /api/auth/google`.
2. Before GIS `initialize`, if the page host is `127.0.0.1`, `location.replace` the same URL on `localhost` (Google’s documented local origin; IP origins often 400).
3. Pass `VITE_GOOGLE_CLIENT_ID` into compose `web` from root `.env` so local GIS uses the same Web client as mock-prod.
4. Local Vite: `Referrer-Policy: no-referrer-when-downgrade` (Google GIS localhost HTTP). Mock-prod Caddy already sends `strict-origin-when-cross-origin` for HTTPS.
5. Runbook [[ops/runbooks/GOOGLE_GIS]]: Console path + exact Authorized JavaScript origins. Human saves them.

## Verify

- [x] Unit: `127.0.0.1:5173` → `localhost:5173`; GIS init config has no `login_uri` / `origin`
- [x] Vault: runbook origins + Console location; compose web interpolates `VITE_GOOGLE_CLIENT_ID`
- [x] `npm test` in `web/`
