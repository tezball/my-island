# Plan: Enable Cursor Automations for plan / implement / review

## Outcome

Three Cursor Automations exist in the Automations editor for `tezball/my-island` and are **Enabled**: PR reviewer, board runner (one ticket), re-review on push. Spec: [[ops/workflow/AUTOMATIONS]].

**Done when** a human has saved and activated all three (this chat cannot), each matches the tables below, none can merge or deploy prod, and the ticket notes list the three dashboard URLs (UUIDs only — no webhook keys). **Kill** if the UI offers auto-merge or a prod deploy tool — do not turn those on; file a new `WF-*` instead.

This is a **plan**. Enabling is a human click in the editor. Local loop already works without them: open Cursor and say “work the next ready ticket”.

## Out of scope

- Saving or activating automations from chat, `/automate`, or this Cloud Agent
- Auto-merge, GitHub “enable auto-merge”, or treating the agent as the required review for `main`
- Prod deploy, `compose.prod`, prod SQL, Jenkins
- Product UI / Spring / PWA / `web/`
- Slack, Linear, PagerDuty, Sentry, webhook triggers (later tickets)
- Changing CI YAML, skills, or hooks in this plan PR
- Secrets, tokens, or webhook API keys in vault notes

## Human clicks (exact)

Cursor cannot fully persist automations from an agent session. `/automate` may **pre-fill a draft**; you still open the editor, check every field, **Save**, then **Activate**.

Official surfaces: [cursor.com/automations](https://cursor.com/automations), [cursor.com/automations/new](https://cursor.com/automations/new), or **Agents Window → Automations**. Trigger and tool names below match Cursor docs (2026-09): *Pull request opened* = non-draft; *Pull request pushed* = new commits on an open PR; scheduled jobs default to **no repository** unless you set one.

### Once — GitHub + dashboard

1. Sign in at [cursor.com](https://cursor.com) as Terry (`tezball`).
2. Open **Dashboard → Integrations** (or Settings → Integrations). Confirm **GitHub** is connected and the Cursor GitHub App can read/write `tezball/my-island`. If not: install the app → grant **only** `tezball/my-island` → return.
3. Open [cursor.com/automations](https://cursor.com/automations).
4. Do **not** enable Cursor-managed **Bugbot**, **Security Agents**, or **PR Routing & Approval** for this ticket (those can approve/route; we want comment-only review plus a one-ticket board runner).
5. Merge this plan PR first so `docs/ops/plans/WF-003.md` is on `main` (prompts may `@` files only after they are on `main`). `SAFETY`, `LOOP`, `AUTOMATIONS`, and `.cursor/skills/ops-loop/SKILL.md` are already on `main`.

### Each automation — editor path (repeat three times)

1. Click **+ New Automation** (top right). Skip marketplace templates.
2. Set **Name** from the table in the next section.
3. **Triggers → Add trigger** — pick the trigger in that table. For GitHub triggers, set repository `tezball/my-island`.
4. **Tools** — match the table. **Pull request creation is on by default**; turn it **off** for the two reviewers. Leave it **on** for the board runner. If a merge / auto-merge / deploy control exists, leave it **off**.
5. **Comment on Pull Request**: on for both reviewers. **Approvals**: **off** (the agent must not Approve as the required review for `main`). If the UI splits “request changes” from Approve, you may enable request-changes only; otherwise the prompt tells the agent to comment `Request changes:` as a top-level PR comment.
6. **Repository**: **Single repository** → `tezball/my-island`. For the **scheduled** board runner this is mandatory — scheduled triggers default to no repo, which cannot open PRs.
7. **Instructions**: paste the matching prompt from this plan (replace nothing except you may `@` the files named there after they are on `main`).
8. **Permissions**: **Team Owned** if you are a team admin (GitHub comments/PRs as `cursor`). Else **Private** (PRs as your GitHub user). Avoid putting webhook secrets in the prompt.
9. **Model**: leave the team default. Automations always use the model’s max context; there is no window toggle.
10. **Computer use**: off if a toggle exists (no browser needed). **Memories**: off for both reviewers.
11. Click **Save**. Then **Activate** / toggle **Enabled** on.
12. Confirm the row on [cursor.com/automations](https://cursor.com/automations) shows Enabled. Copy the automation URL (contains a UUID) into [[ops/tickets/WF-003]] Notes. Do **not** paste webhook API keys.

If Save is blocked, stop. Do not workaround with Jenkins, a GitHub Action that merges, or a second API language.

### 1. Paste: PR reviewer

```
You are the PR reviewer for tezball/my-island. Wear the REVIEWER hat only.

Read @docs/ops/workflow/SAFETY.md @docs/ops/workflow/LOOP.md @docs/ops/workflow/CI.md @docs/ops/workflow/AUTOMATIONS.md @.cursor/skills/ops-loop/SKILL.md

This run is a non-draft pull request opened against tezball/my-island. If the PR is still a draft, stop and do nothing.

Does:
- Review the diff against the linked ticket (docs/ops/tickets/<id>.md) and plan (docs/ops/plans/<id>.md). If the PR body has no ticket, say so and review SAFETY anyway.
- Comment on the PR (top-level; inline only for a concrete line).
- If SAFETY is violated, comment with a first line exactly: Request changes: <reason>
- Check: no merge / auto-merge in the diff’s CI tricks; no secrets in notes; no prod deploy; no legacy Jenkins from `docs/automation/` (house Jenkins in compose is OK); WF-* tickets must not add product UI; product code only if the ticket id is PRD-* AND ticket status is implement.

Does not:
- Merge, enable auto-merge, push commits, approve as the required review for main, deploy prod, write secrets into the vault.

Tools: Comment on Pull Request only. Do not create a new PR. Do not Approve.

Output: one PR comment. First line LGTM (human may merge) or Request changes: <reason>. Then a short findings list.
```

### 2. Paste: board runner

```
You are the board runner for tezball/my-island. One ticket, then stop. Callsign-style: factory / automation-expert when the ticket owner is automation-expert; otherwise wear the ticket’s owner hat.

Checkout main. Read @docs/ops/HOME.md @docs/ops/BOARD.md @docs/ops/workflow/SAFETY.md @docs/ops/workflow/LOOP.md @docs/ops/runbooks/TICKET_LOOP.md @.cursor/skills/ops-loop/SKILL.md @docs/ops/plans/WF-003.md

Skip:
- type: epic (including PRD-000 / WF-000). Work a child.
- Product / application code (Spring, PWA, web/, services/ aside from docs) unless the ticket id starts with PRD- AND ticket status is implement.
- More than one ticket. Merge. Prod. Jenkins. Secrets in notes.

Pick at most one:
1. Planner: python3 ops/scripts/next_ticket.py --role planner — if a non-epic ticket is ready and has no plan, write docs/ops/plans/<id>.md from docs/ops/templates/plan.md, set ticket status: plan and plan: "[[ops/plans/<id>]]", python3 ops/scripts/board_sync.py, open a PR, stop.
2. Else implementer: python3 ops/scripts/next_ticket.py --role implementer — only if that ticket has an approved plan (or human-approved) and no open PR. Implement that one ticket. Open a PR. Set status: review and pr: <url>. Sync the board. Stop.
3. Else do nothing. Do not invent work. Do not review PRs (other automations do that).

Verify: python3 -m pytest ops/tests -q -m "not stack" when you touch the vault. No --no-verify. No gh pr merge.

PR title: <id>: <ticket title>. Body links docs/ops/tickets/<id>.md and docs/ops/plans/<id>.md. No agent URLs in the PR body.
```

### 3. Paste: re-review on push

```
You are the PR re-reviewer for tezball/my-island. Same rules as the PR reviewer, shorter: only the new commits on this open PR.

Read @docs/ops/workflow/SAFETY.md @docs/ops/workflow/LOOP.md @docs/ops/workflow/AUTOMATIONS.md @.cursor/skills/ops-loop/SKILL.md

If the PR is a draft, stop. Review only the commits just pushed, plus SAFETY on the whole diff if a new commit could merge, secret-log, or prod-deploy.

Does: comment. If SAFETY is violated, first line Request changes: <reason>.
Does not: merge, push, Approve as the required review, create another PR, prod.

Tools: Comment on Pull Request only.
```
