# Plan: PostGIS image has no ARM64 (app start fails on Apple Silicon)

## Outcome

`./scripts/app start` works on Apple Silicon. Local compose and catalog Testcontainers use one PostgreSQL 17 + PostGIS 3.5 image that publishes **linux/amd64 and linux/arm64**. Done when start no longer hits “no matching manifest for linux/arm64/v8”, amd64 CI/Cloud still come up, and vault tests pin the same image.

## Out of scope

- Consumer PWA ([[ops/tickets/PRD-003]])
- GHCR of *our* images ([[ops/tickets/WF-012]])
- Digest-pinned deploys
- Building a custom PostGIS Dockerfile in-repo
- `platform: linux/amd64` qemu workaround
- Merging the PR

## Steps

1. File [[ops/tickets/WF-024]]. Owner: eng-infra. Parent: [[ops/tickets/WF-001]].
2. Point `compose.yml` `postgres.image` at `ghcr.io/baosystems/postgis:17-3.5` (Bao Systems multi-arch rebuild of docker-postgis; Hub `postgis/postgis:17-3.5*` is amd64-only). Comment why.
3. Point catalog Testcontainers at the same tag (`asCompatibleSubstituteFor("postgres")`).
4. Update [[ops/workflow/LOCAL]] (image name + `docker compose down -v` if an alpine volume already exists).
5. Assert the shared image in `ops/tests/test_dev_env.py`. Do not rewrite historical [[ops/plans/PRD-001]].
