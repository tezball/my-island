# Plan: Review-gated automerge

## Outcome

Ready same-repo non-draft PRs squash-merge only when GHA `unit` + `catalog` + `web` + `stack` are green **and** a current `APPROVE` exists from someone who is not `github-actions[bot]` and not the PR author. `CHANGES_REQUESTED` blocks. Chat never `gh pr merge`. No production Environment. Done when SAFETY / LOOP / CI / DECISIONS / vault tests pin that gate and the merge job no longer `createReview` APPROVE.

## Out of scope

- App / PWA UI ([[ops/tickets/PRD-031]] waits until this is on `main`)
- Jenkins `H/5` mock-prod, [[ops/tickets/WF-048]] `createWorkflowDispatch` after squash, `mock-prod-signal`
- GitHub Environment `production`, `compose.prod`, prod SSH
- Draft PRs, fork PRs, Cursor Automations merge ([[ops/tickets/WF-003]])
- Merging from chat (`gh pr merge`)

## Steps

1. **Remove CI auto-APPROVE.** Delete `github.rest.pulls.createReview` with `event: 'APPROVE'` from the GHA merge job in [`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml). Do not replace it with another bot approve.

2. **Re-run the merge job on `pull_request_review` (`submitted`).** A late agent Approve must be able to squash after CI is already green. Keep squash only for non-draft, same-repo PRs. Keep `merge_method: 'squash'` and the WF-048 `createWorkflowDispatch` on `main`.

3. **Waiting for review must not go red.** If `unit` + `catalog` + `web` + `stack` are green but there is no valid Approve yet, the merge job **skips/succeeds** (`waiting for review`) — do **not** `core.setFailed`, do **not** merge. Same if CI is still pending (`waiting for CI`). Red CI: do not merge; do not fail the merge job in a way that paints the PR red.

4. **Valid Approve.** Query PR reviews on the head SHA. Count `APPROVE` only when:
   - `state` is `APPROVED`
   - actor login is **not** `github-actions[bot]`
   - actor is **not** the PR author
   - review `commit_id` equals the PR head SHA (stale Approve does not count)
   `CHANGES_REQUESTED` that is not dismissed **blocks**, even if an Approve also exists.

5. **Do not cancel in-flight CI.** Today `concurrency` is `CI-${{ github.ref }}` with `cancel-in-progress: true`. A `pull_request_review` event must **not** cancel `unit` / `catalog` / `web` / `stack`. Either (preferred) a sibling workflow for merge-on-review, or skip those four jobs unless `pull_request`/`push`/`workflow_dispatch` **and** a concurrency group that does not cancel the PR CI run. On review events, read check-runs for those four job names on the head SHA — do not re-run the suites.

6. **Pin the lock in docs + tests** (this is the implementer, not the planner):
   - [[ops/workflow/SAFETY]] item 1: green CI **plus** valid non-author Approve; bot auto-APPROVE gone
   - [[ops/workflow/LOOP]] reviewer row: **may** Approve or Request changes; **must not** merge or push. Implementer **must not** approve their own PR (already in LOOP; keep it)
   - [[ops/workflow/CI]] branch/PR + automerge paragraphs; [[ops/workflow/PIPELINE]] “Approve + squash-merge” row; [[ops/workflow/DX]] GHA line
   - [[ops/company/DECISIONS]] 2026-09-12 #8 **and** a 2026-09-20 lock that replaces the WF-025 auto-APPROVE. Keep no-prod. CD line in [`product/STACK.md`](../../product/STACK.md) if it still says “auto-merge when CI is green” with no review
   - `.cursor/rules/no-prod.mdc`, `.cursor/skills/ops-loop/SKILL.md`, `.cursor/skills/reviewer/SKILL.md` (reviewer **may** Approve / Request changes; still no merge/push)
   - `ops/tests` (`test_wf_025_no_prod_and_automerge` and friends): pin **no** `createReview` APPROVE, `pull_request_review`, waiting-for-review success, valid-Approve rules, drafts/forks skipped. Keep the no-prod assertions.

7. **Hats.** Reviewer session may submit Approve or Request changes. Still must not merge or push. Implementer of a PR must not Approve that PR. Chat never `gh pr merge` — Actions squash-merges when the gate passes.
