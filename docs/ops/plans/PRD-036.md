# Plan: Host and Stay thin slice

## Outcome

Same as [`product/HOST-STAY.md`](../../product/HOST-STAY.md). A signed-in host adds one or more Stays. A Stay is a new place, not a claim on the 101 POIs. Kinds are campsite, bed and breakfast, apartment, glamping, and lodge. One page per Stay.

The Stay stays hidden until automatic review finishes clean. Any edit hides it again. Review error or timeout keeps it hidden. Review order is tech, fit, then conduct. A website, if present, must load and read as a place to stay. Review does not follow redirects. A 3xx is “did not load”, the same as a down site. Fit failures are feedback. A ban hides every Stay of that host and blocks new submissions. Phone and email show on the public page when present.

Admin is the Google account checked on the server. Actions are run review again and unban. Unban does not publish. There is no hand-publish. Public Place POST stays closed.

## Out of scope

- Dates, payment, messages, hotels
- Supplier drafts and curator publish ([[ops/tickets/PRD-033]] stays `plan`)
- Role homes and the support help path ([[ops/tickets/PRD-034]] stays `plan`; this slice does not mark it done)
- Promoting [[ops/tickets/PRD-016]]–[[ops/tickets/PRD-029]]
- GitHub Environment `production`, `compose.prod`, prod SSH

## Steps

1. Authenticated host API. Public Place POST stays closed.
2. Wizard and one public page per Stay. County comes from the Ireland pin.
3. Automatic review, fail-closed, including a website fetch that does not follow redirects.
4. Admin console for the configured Google account: all Stays, stuck reviews, banned accounts. Run review again. Unban does not publish.
5. Seed the four demo password hosts. Do not pre-fill `tezball86@gmail.com`.
6. After merge, mock-prod deploy from `main` and confirm on https://fishing-journals.com. Agents never SSH.
