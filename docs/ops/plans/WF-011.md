# Plan: Playwright cron vs fishing-journals.com (not a merge gate)

## Outcome

**Only Playwright is outside merge CI.** Playwright never joins automerge `needs` and never runs inside `unit`/`catalog`. A scheduled job (recommend **6h**) runs against https://fishing-journals.com/. Agents drive the same UI via Playwright MCP on demand. Post-deploy confirm does **not** wait on this suite. Catalog API, Chaos, and ZAP stay **on merge** (other tickets). Gatling is trickle + weekly ([[ops/tickets/WF-042]]), not merge load.

## Out of scope

- Playwright as a merge gate / required PR check
- Playwright inside `unit` / `catalog`
- Moving Chaos / ZAP to cron
- Full Gatling performance on every merge
- Next.js CI
- Replacing HTTP/API post-deploy smoke ([[ops/tickets/WF-040]])
- Chat `gh pr merge`

## Steps

1. Document in [[ops/workflow/CI]] + [[ops/workflow/TEST_STACK]]: browser lane is cron + MCP; catalog/Chaos/ZAP stay merge CI. Gatling is trickle + weekly, **not** merge load ([[ops/tickets/WF-042]]). Fail path is [[ops/tickets/WF-045]].
2. Add a scheduled GHA (and/or Jenkins) Playwright workflow against the public test URL. Interval **6 hours** unless a tighter cron is written in the PR. Failures page automation-expert; they do not block automerge.
3. Keep Playwright MCP in the agent pack ([[ops/tickets/WF-042]]). On-demand, not CI-required.
4. Do not start compose-for-Playwright on product PRs as a required check.
