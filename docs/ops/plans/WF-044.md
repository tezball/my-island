# Plan: ZAP-style scanner in CI against local compose

## Outcome

Every merge runs an OWASP **ZAP-style** DAST job in Jenkins + GHA against **local compose and/or Testcontainers**. Automerge waits on it. Public https://fishing-journals.com/ is **not** the primary scan. Do **not** move ZAP to cron. `unit`/`catalog` still do not invoke the scanner (fast UI-less jobs; no Playwright there either).

## Out of scope

- Making fishing-journals.com the merge-gate scan target
- Folding ZAP into default `unit` / `catalog` Maven/pytest
- Moving this job to cron / scheduled-only CI
- Paid DAST SaaS as system of record
- Chaos Monkey ([[ops/tickets/WF-043]])
- Secrets, API keys, or scan reports with tokens in `docs/`
- Chat `gh pr merge`

## Steps

1. Pick OWASP ZAP (baseline / zap2docker) or a documented equivalent. Add a **dedicated** GHA job + Jenkins stage. Dual-run.
2. Point it at job-started local compose and/or Testcontainers URLs, not the public apex.
3. Fail on the house severity bar (High/critical unless the PR documents a tighter/looser bar). Reports as CI artifacts, not git.
4. Wire **every merge**: GHA `automerge` `needs` includes this job. Do not put the scanner inside `unit`/`catalog` bodies.
5. Document in [[ops/workflow/CI]] + [[ops/workflow/TEST_STACK]]: merge CI includes ZAP; Playwright is the only cron/MCP lane. Catalog writes lock C ([[ops/tickets/WF-046]]): Place POST must not be an expected open verb.
